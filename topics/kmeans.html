K-Means Clustering

Clustering (unsupervised) Dataset: Kaggle vjchoudhary7/customer-segmentation-tutorial-in-python Library: scikit-learn

What it is

Yeh kya hai

K-Means is an unsupervised algorithm that splits data into k groups (clusters) without ever seeing a label. You choose k in advance — "split my customers into 5 groups" — and the algorithm finds the 5 natural groupings hiding in the features.

K-Means ek unsupervised algorithm hai jo data ko k girohon (clusters) mein taakta hai bina koi label diye..

The intuition is simple: a cluster is a bunch of points that sit close together, and each cluster can be represented by its center (the centroid — the mean position of all its members). K-Means alternates between two steps: assign every point to its nearest centroid, then move each centroid to the mean of the points it just captured. Repeat until nothing moves.

Samajh aasan hai: cluster woh points ka giroh hai jo aas paas baithe hon.

Unlike DBSCAN (Topic 03), K-Means needs k upfront, works best on round, similarly-sized blobs, and always assigns every point to some cluster — there are no "noise" points. In return it's fast, scales to millions of rows, and gives you a centroid per cluster you can inspect and use for prediction on new data.

DBSCAN (Topic 03) ke ulat, K-Means ko pehle se k chahiye.

It's the classic customer-segmentation tool: feed in income and spending score, and out come segments like "high income, low spending" that marketing teams can target differently.

Yeh classic customer-segmentation tool hai.

The math inside

Andar ka math

K-Means tries to minimize the within-cluster sum of squares (WCSS) — the total squared distance between every point and the centroid of its assigned cluster:

K-Means within-cluster sum of squares (WCSS) ko minimize karne ki koshish karta hai.

Objective = min Σk=1..K Σx ∈ cluster k ||x − centroidk||²

This is the total squared Euclidean distance from every point to the centroid of its assigned cluster; smaller means tighter clusters.

Yeh har point se uske cluster ke centroid tak kul squared Euclidean doori hai.

Centroid: the center of a cluster — literally the mean (average) of the coordinates of all points in that cluster. Point (x̄, ȳ) where x̄ is the average x of the members. The mean is already explained in Core Concepts.
WCSS / elbow method: WCSS = the total within-cluster sum of squares across all clusters (the objective above, summed over the whole dataset). The elbow method runs K-Means for k = 1, 2, 3, … and plots WCSS vs k. WCSS always drops as k grows, but at some k the drop suddenly flattens — that bend (the "elbow") is the natural number of clusters, because adding more clusters past it stops helping.

The algorithm itself, step by step:

Algorithm khud, qadam ba qadam:.

1. Pick k starting centroids randomly (k random points)

Initialization — where the algorithm starts.

Initialization — algorithm kahan se shuru hota hai..

2. Assign: each point → nearest centroid (by Euclidean distance)

Every point joins the cluster of the centroid closest to it.

Har point apne sab se qareeb centroid ke cluster mein shamil ho jata hai..

3. Update: centroidk = mean of all points assigned to cluster k

Each centroid walks to the average position of its members — the step that shrinks WCSS.

Har centroid apne members ki average jagah ki taraf chalta hai.

4. Repeat 2–3 until assignments stop changing (converged)

Assignment and update keep alternating until every point stays with its cluster — then the centroids are stable.

Assignment aur update barabar badalte rehte hain jab tak har point apne cluster mein tikta nahi jata.

Note that distances are Euclidean distance, already explained in Core Concepts, and centroid updates use the mean, also in Core Concepts. Because the algorithm is built on distances, feature scaling (why we StandardScale below) matters — that's in Core Concepts too.

Dhyan do ke dooriyan Euclidean distance hain, jo Core Concepts mein samjhayi ja chuki hain.

Dataset (Kaggle)

Dataset (Kaggle)

Mall Customers — kagglehub slug vjchoudhary7/customer-segmentation-tutorial-in-python, file Mall_Customers.csv. It has 200 rows, one per mall customer, with 5 columns: CustomerID, Genre (gender), Age, Annual Income (k$), and Spending Score (1–100, assigned by the mall based on buying behavior). There is no target column — that's the point: this is unsupervised learning, and the "answer" (customer segments) is something K-Means discovers on its own from just income and spending score.

Practice code — run in Google Colab, top to bottom

Practice code — Google Colab mein upar se neeche chalayein

Blocks must run in order. Copy each block into Colab (or a Jupyter notebook) one at a time and run it before moving to the next — later blocks depend on variables from earlier ones.
BLOCK 1: Imports

Everything we need: pandas/numpy for data, kagglehub to fetch the dataset, sklearn for scaling and K-Means, matplotlib for plots.

Jo kuch chahiye: pandas/numpy data ke liye.

# Import pandas for DataFrames and numpy for numeric arrays
import pandas as pd
import numpy as np
# kagglehub downloads Kaggle datasets straight into Colab
import kagglehub
# glob finds the downloaded CSV file path on disk
import glob
# StandardScaler puts features on the same scale (critical for distance-based K-Means)
from sklearn.preprocessing import StandardScaler
# KMeans is the clustering model itself
from sklearn.cluster import KMeans
# matplotlib for the elbow plot and the cluster scatter
import matplotlib.pyplot as plt
BLOCK 2: Download the dataset with kagglehub

kagglehub pulls the dataset from Kaggle and returns the local folder it saved to; glob then finds the CSV inside it.

kagglehub dataset Kaggle se laata hai aur local folder wapas deta hai.

# Download the Mall Customers dataset; path is the local folder kagglehub created
path = kagglehub.dataset_download("vjchoudhary7/customer-segmentation-tutorial-in-python")
# Search that folder for the CSV file (glob returns a list of matching paths)
csv_files = glob.glob(path + "/Mall_Customers.csv")
# Print what we found so we can confirm the file is there
print("Found:", csv_files)
BLOCK 3: Load and look at the data

Read the CSV into a DataFrame and take a first look at shape, columns, and a few rows.

CSV ko DataFrame mein parho aur pehli nazar daalo.

# Load the CSV into a pandas DataFrame
df = pd.read_csv(csv_files[0])
# 200 rows, 5 columns expected
print(df.shape)
# Column names and dtypes
print(df.info())
# First 5 rows to eyeball the values
print(df.head())
BLOCK 4: Select the two clustering features

We cluster on Annual Income and Spending Score only — two interpretable axes. CustomerID is just a row label, not behavior, so we drop it.

Hum sirf Annual Income aur Spending Score par cluster karte hain.

# Keep only the two behavioral features we want to cluster on
X = df[["Annual Income (k$)", "Spending Score (1-100)"]].copy()
# Quick sanity check: 200 rows, 2 columns, no missing values
print(X.describe())
print(X.isnull().sum())
BLOCK 5: Scale the features

K-Means is built on Euclidean distance. Income spans ~15–137 while spending spans ~1–99; unscaled, income differences would dominate and squash the spending information. StandardScaler centers both columns at mean 0 with std 1.

K-Means Euclidean distance par bana hai. Income ka span.

# Create the scaler (mean 0, std 1 for each column)
scaler = StandardScaler()
# Fit the scaler to X and transform it in one step -> numpy array
X_scaled = scaler.fit_transform(X)
# Same shape, but now both features contribute equally to distances
print(X_scaled[:5])
BLOCK 6: Elbow method — choose k

We don't know the right number of clusters, so we run K-Means for k = 1..10, record WCSS (inertia_) each time, and look for the elbow — the k where the curve bends and adding clusters stops helping much.

Clusters ki sahi tadaad maloom nahi, is liye k = 1..10 ke liye K-Means chalate hain.

# Try every k from 1 to 10 and store the WCSS of each run
wcss = []
for k in range(1, 11):
    # n_init=10 means 10 random restarts; sklearn keeps the best (lowest WCSS) run
    km = KMeans(n_clusters=k, random_state=42, n_init=10)
    km.fit(X_scaled)
    # inertia_ is sklearn's name for WCSS: sum of squared distances to nearest centroid
    wcss.append(km.inertia_)

# Plot WCSS vs k — the "elbow" is the natural cluster count
plt.figure(figsize=(7, 4))
plt.plot(range(1, 11), wcss, marker="o")
plt.xlabel("Number of clusters (k)")
plt.ylabel("WCSS (inertia)")
plt.title("Elbow Method")
plt.grid(True)
plt.show()
# Expect a sharp bend at k=5: WCSS plummets until 5, then flattens
BLOCK 7: Fit K-Means with k = 5

The elbow points at 5, so we fit the final model with 5 clusters. random_state makes results reproducible; n_init=10 retries from 10 random starting positions because K-Means can otherwise get stuck in a bad local optimum.

Elabow 5 ki taraf ishara karta hai, to final model 5 clusters ke saath fit karte hain.

# Final model: 5 clusters, 10 restarts, fixed seed for reproducibility
kmeans = KMeans(n_clusters=5, random_state=42, n_init=10)
# Fit on the scaled features — no labels anywhere (unsupervised)
kmeans.fit(X_scaled)
# WCSS of the fitted 5-cluster solution
print("WCSS (inertia):", round(kmeans.inertia_, 2))
BLOCK 8: Labels and centroids

labels_ gives the cluster number (0–4) of every customer; cluster_centers_ holds the 5 centroid coordinates in scaled space. We inverse-transform them back to real dollars/score so they're readable.

labels_ har customer ka cluster number (0-4) deta hai.

# Cluster assignment (0..4) for each of the 200 customers
labels = kmeans.labels_
# Add the cluster back to the original (unscaled) dataframe for profiling
df["Cluster"] = labels
# 5 centroids in scaled space -> convert back to real units
centers_real = scaler.inverse_transform(kmeans.cluster_centers_)
print("Centers (income k$, spending score):")
print(np.round(centers_real, 1))
# How many customers per segment
print(df["Cluster"].value_counts().sort_index())
BLOCK 9: Visualize the 5 segments

Scatter every customer colored by cluster, and mark the 5 centroids with black X's — one look should show 5 clean blobs with a centroid in the heart of each.

Har customer ko cluster ke rang se bikhrao aur 5 centroids nishaan lagao.

plt.figure(figsize=(8, 6))
# One colored scatter per cluster (loop keeps colors consistent)
for c in range(5):
    subset = df[df["Cluster"] == c]
    plt.scatter(subset["Annual Income (k$)"], subset["Spending Score (1-100)"], label=f"Cluster {c}", s=40)
# Black X markers at the 5 centroid positions (real units)
plt.scatter(centers_real[:, 0], centers_real[:, 1], c="black", marker="X", s=220, label="Centroids")
plt.xlabel("Annual Income (k$)")
plt.ylabel("Spending Score (1-100)")
plt.title("Mall Customer Segments (K-Means, k=5)")
plt.legend()
plt.grid(True)
plt.show()
BLOCK 10: Profile and name each segment

groupby-mean turns numbers into a story: average income, spending, and age per cluster. That's how we name the 5 customer types and hand marketing something actionable.

groupby-mean numbers ko kahani mein badal deta hai.

# Mean of each feature per cluster — the "profile card" of every segment
profile = df.groupby("Cluster")[["Annual Income (k$)", "Spending Score (1-100)", "Age"]].mean().round(1)
print(profile)

# Human names for the 5 typical segments in this dataset:
# 0: high income, low spending  -> "careful-rich" (earn much, spend little)
# 1: low income, low spending   -> "careful"      (small budget, watches wallet)
# 2: average income, avg spend  -> "standard"     (the steady middle mass)
# 3: low income, high spending  -> "careless"     (spends beyond its means)
# 4: high income, high spending -> "careless-rich" (the VIPs marketers love)

BLOCK 11: Predict the segment of a new customer

K-Means is a real model: predict assigns a brand-new customer to the nearest fitted centroid — same rule the training loop used. Remember to scale the new input with the SAME fitted scaler.

K-Means ek asli model hai: predict naya customer.

# A new customer: 80k$ income, spending score 75
new_customer = [[80, 75]]
# Scale with the SAME scaler fitted earlier (never refit on new data)
new_scaled = scaler.transform(new_customer)
# Assign to the nearest of the 5 centroids
cluster = kmeans.predict(new_scaled)
print("New customer belongs to segment:", cluster[0])
# That's a high-income, high-spending customer -> a "careless-rich" VIP prospect

Combining with other algorithms (project ideas)

Dusre algorithms ke saath milana (project ideas)

K-Means segments → one model per segment (Topic 09). Cluster customers first with K-Means, then fit a separate Multiple Regression inside each cluster (e.g. predict spending from age + income per segment). The per-segment models usually beat one global model because each cluster's relationship is simpler and cleaner.

K-Means segments → har segment ka ek model (Topic 09).

K-Means → logistic churn per cluster (Topic 05). Use K-Means to build behavioral segments, then train a Logistic Regression churn classifier on each segment. You not only predict WHO churns but also get "which type of customer" for free — that combination is what actually shapes the retention offer.

K-Means → har cluster ka logistic churn (Topic 05).

PCA first, then K-Means on the PCs (Topic 07). With many correlated features, run PCA, keep the top components, and cluster in that smaller space. Distances become more meaningful (less noise), it's cheaper, and you can even plot clusters on PC1 vs PC2.

Pehle PCA, phir PCs par K-Means (Topic 07).

K-Means vs DBSCAN sanity check (Topic 03). Run both on the same data — K-Means forces k round clusters, DBSCAN finds arbitrary shapes and labels outliers as noise. Comparing the two segmentations on the same customers is a great notebook exercise and interview story.

K-Means vs DBSCAN aazmaish (Topic 03).

Interview Q&A

Interview ke sawal-jawab

How do you choose the number of clusters k?
Main tool: the elbow method — run K-Means for k = 1..10, plot WCSS vs k, and pick the bend where adding another cluster stops reducing WCSS much. Alternatives: the silhouette score (how well-separated clusters are, tested over several k) or a business constraint — if marketing can only handle 4 campaigns, k = 4 regardless of the elbow.
What is WCSS and what does the inertia_ attribute contain?
WCSS is the within-cluster sum of squares: the total of squared Euclidean distances between every point and its assigned centroid. K-Means tries to minimize it. sklearn's inertia_ is exactly WCSS after fitting.
Why does feature scaling matter for K-Means?
K-Means assigns points by Euclidean distance. If one feature has a much bigger range (income in 15–137k$) than another (score 1–99), that feature dominates the distance and clustering is effectively done on one axis. StandardScaler puts every feature at mean 0, std 1 so they contribute equally.
What is a centroid?
The center of a cluster: the mean of the coordinates of all points currently assigned to it. After convergence each centroid is the point that minimizes the sum of squared distances to its cluster members.
Does K-Means always find the best solution?
No. It minimizes WCSS greedily and converges to a local optimum that depends on the random starting centroids. That's why we set n_init=10 — sklearn restarts from 10 random initializations and keeps the run with the lowest WCSS (k-means++ also spreads the initial centroids out smartly, which is sklearn's default).
How is K-Means different from DBSCAN?
K-Means needs k upfront, prefers round similarly-sized clusters, and assigns every point somewhere. DBSCAN (Topic 03) needs no k, finds arbitrary-shaped clusters from density, marks lonely points as noise, and struggles less with outliers but more with varying densities. Use K-Means for compact blobs, DBSCAN for weird shapes and outlier detection.
Is K-Means supervised or unsupervised, and how can you evaluate it with no labels?
Unsupervised — no target, the algorithm invents the groups. Without labels you evaluate with internal metrics: WCSS/elbow, silhouette score (cohesion vs separation). If labels do exist for research, you can use them indirectly (e.g. purity) — but unlike the Confusion Matrix (Topic 01), there's no prediction-vs-truth table, because there's no truth column.
Why would you run PCA before K-Means?
Three reasons: PCA (Topic 07) removes correlation between features so Euclidean distance isn't double-counting redundant information, it cuts noise and dimensionality so clustering is faster and often cleaner, and clustering on the top 2 PCs lets you actually plot the segments.
Walk me through one full iteration of K-Means.
Assign: compute the Euclidean distance from every point to every centroid and attach each point to its nearest one. Update: recompute each centroid as the mean of the coordinates of the points now assigned to it. Check: if no point changed clusters, stop — otherwise repeat. Each full iteration can only decrease (or keep) WCSS, which is why the loop converges.
