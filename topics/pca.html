PCA (Principal Component Analysis)

Dimensionality reduction (unsupervised) Features kam karna (unsupervised) Dataset: Kaggle uciml/iris Library: sklearn (StandardScaler, PCA, LogisticRegression)

What it is

PCA takes a dataset with many features (columns) and squeezes it down to fewer new features while keeping as much of the original information (variance) as possible. As your teacher put it: "PCA converts high features to low features." If you have 4 measurements per flower, PCA can find 2 new "super-features" that carry almost all of the 4 original measurements' story.

PCA aik aise dataset — jis mein bohat saari features (columns) hon — ko chhoti si tayyada nayi features tak le aata hai, lekin original information (variance) jitni ho sake bachata rehta hai. Jaise aapke teacher ne kaha: "PCA converts high features to low features." Agar aapke paas har phool ke 4 measurements hon, to PCA 2 nayi "super-features" dhoond sakta hai jo 4 original measurements ki taqreeban poori kahani apne andar rakhte hain.

The trick is that the new features are not picked from the old ones — they are new directions built as combinations of the old ones. Each direction (a principal component) is chosen to point where the data is most spread out. Direction 1 (PC1) captures the most variance, PC2 the next most, and so on, and every component is perpendicular (uncorrelated) to the others.

Kamaal yeh hai ke nayi features purani mein se nikaali nahi jaatin — woh purani features ke combinations se banaye gaye naye directions hain. Har direction (aik principal component) aisa chuna jaata hai ke data jahan sab se zyada spread ho wahin ishara kare. Direction 1 (PC1) sab se zyada variance pakadta hai, PC2 us se thora kam, aur aise hi aage — aur har component baqi sab ke perpendicular (uncorrelated) hota hai.

PCA is unsupervised: it never looks at the target column (Species). It only looks at how the inputs spread. That is why, when we plot Iris flowers using just PC1 and PC2, the three species form visible clusters even though PCA was never told the labels — a nice bridge to K-Means and DBSCAN.

PCA unsupervised hai: yeh kabhi target column (Species) ko nahi dekhta. Yeh sirf dekhta hai ke inputs kaise phaile hue hain. Isi liye jab hum Iris ke phool sirf PC1 aur PC2 se plot karte hain to teen species khud-ba-khud nazar aane wale clusters banati hain — halanke PCA ko labels ka bataya hi nahi gaya tha. Yeh K-Means aur DBSCAN tak pohanchne ka aik acha pul hai.

One warning your teacher's comparison makes clear: "SVM is totally opposite to PCA." SVM is a classifier (it draws decision boundaries to predict labels), while PCA is a reducer (it compresses features and predicts nothing). They are not rivals — they work at different jobs, and we'll even chain them (PCA → SVM) in the pipelines section.

Aik warning jo aapke teacher ke comparison se saaf hota hai: "SVM is totally opposite to PCA." SVM aik classifier hai (yeh labels predict karne ke liye decision boundaries khinchta hai), jabke PCA aik reducer hai (yeh features ko compress karta hai aur kuch predict nahi karta). Yeh dosre ke rivaled nahi hain — dono ke alag kaam hain, aur hum inhein aage pipelines section mein jor kar bhi dekhein ge (PCA → SVM).

The math inside

This is exactly the route from your class notes: mean → covariance matrix → characteristic equation → eigenvalues → eigenvectors → projection. sklearn's PCA does this same math under the hood (via a faster matrix factorization called SVD, which finds the same directions).

Yeh bilkul wohi raasta hai jo aapke class notes mein hai: mean → covariance matrix → characteristic equation → eigenvalues → eigenvectors → projection. sklearn ka PCA andar hi andar yehi math karta hai (aik tez matrix factorization ke zariye jise SVD kehte hain, jo wohi directions dhoondta hai).

Step 1 — subtract the mean. For each feature, take its mean and subtract it from every value, so each column is centered at 0:

Step 1 — mean minus karein. Har feature ka mean nikaal kar har value mein se minus kar dein, taake har column ka markaz 0 ho jaye:

xcentered = x − mean(x),   ycentered = y − mean(y)

This centers the data cloud on the origin so "spread" is measured from the middle. The mean itself is already explained in Core Concepts.

Is se data ka cloud origin par aa jata hai taake "spread" beech se naapa ja sake. Mean khud Core Concepts mein already samjhaya gaya hai.

Step 2 — build the covariance matrix. From the centered columns, compute the four entries your notes list as XX, XY, YX, YY:

Step 2 — covariance matrix banayein. Centered columns se woh chaar entries nikaalein jo aapke notes XX, XY, YX, YY likhte hain:

C = [ cov(X,X)   cov(X,Y) ]
   [ cov(Y,X)   cov(Y,Y) ]
cov(X,Y) = Σ (xi − mean(x)) · (yi − mean(y)) / (n − 1)

The diagonal entries (XX, YY) are the variances of each feature; the off-diagonals (XY and YX, always equal) say how the features move together. Covariance is already explained in Core Concepts. With 4 features you get a 4×4 version of this same matrix.

Diagonal wali entries (XX, YY) har feature ki variance hoti hain; off-diagonal entries (XY aur YX, hamesha barabar) batati hain ke features saath saath kaise hilti hain. Covariance Core Concepts mein already samjhaya gaya hai. 4 features par aapko isi matrix ka 4×4 version milta hai.

Step 3 — solve the characteristic equation. Eigenvalues λ are the numbers for which the matrix C stretched a direction without rotating it. They are found by setting the determinant of (C − λI) to zero — exactly the "characteristic equation (quadratic), determinant" step in your notes:

Step 3 — characteristic equation solve karein. Eigenvalues λ woh numbers hain jin ke liye matrix C kisi direction ko ghumaaye bagair usay khinch deta hai. Yeh (C − λI) ke determinant ko zero rakh kar nikaale jaate hain — bilkul woh "characteristic equation (quadratic), determinant" step jo aapke notes mein hai:

|C − λI| = 0

Here I is the identity matrix (1s on the diagonal, 0s elsewhere) and the bars mean determinant (already explained in Core Concepts). For a 2×2 covariance matrix, expanding the determinant gives a quadratic equation in λ:

Yahan I identity matrix hai (diagonal par 1, baqi sab 0) aur bars ka matlab determinant hai (Core Concepts mein already samjhaya gaya). 2×2 covariance matrix ke liye determinant expand karne se λ mein quadratic equation banti hai:

|C − λI| = (xx − λ)(yy − λ) − (xy)² = λ2 − Aλ + B = 0

Matching your notes: the square value = A (the coefficient that sits on λ2 after expanding — here it is 1, and A works out to the sum of the diagonal variances) and λ = B's equation — B is the constant term (it equals the determinant of C). Solving this quadratic with the familiar formula gives the two eigenvalues:

Aapke notes se match karte hue: square value = A (expand karne ke baad λ2 ke saath baithne wala coefficient — yahan yeh 1 hai, aur A diagonal variances ka sum nikalta hai) aur the λ = B equation — B constant term hai (yeh C ke determinant ke barabar hota hai). Is quadratic ko mashhoor formula se solve karne par do eigenvalues milte hain:

λ = (A ± √(A² − 4B)) / 2

Each solution λ is an eigenvalue: the amount of variance along one hidden direction of the data. For a 4-feature dataset like Iris, the same idea gives a degree-4 polynomial with 4 eigenvalues — but sklearn solves it numerically so you never write that by hand.

Har solution λ aik eigenvalue hai: data ki kisi chhupi hui direction ke saath variance ki miqdaar. Iris jaise 4-feature dataset par isi idea se degree-4 polynomial banta hai jiske 4 eigenvalues hote hain — lekin sklearn ise numerically solve karta hai, to aapko kabhi haath se likhna nahi padta.

Step 4 — find the eigenvectors (principal axes). For each eigenvalue λ, plug it back and solve:

Step 4 — eigenvectors dhoondein (principal axes). Har eigenvalue λ wapis rakh kar solve karein:

(C − λI) · v = 0   →   v = the eigenvector for that λ

The eigenvector v is a direction the covariance matrix does not rotate — one principal axis. Eigenvectors and eigenvalues are already explained in Core Concepts.

Eigenvector v woh direction hai jise covariance matrix ghumaata nahi — aik principal axis. Eigenvectors aur eigenvalues Core Concepts mein already samjhaaye gaye hain.

Step 5 — sort by λ, keep top k, project. Sort the eigenvectors by their eigenvalues (biggest variance first), keep the top k (e.g. 2), stack them as rows of a matrix W, and rotate the data onto the new axes:

Step 5 — λ se sort karein, top k rakhein, project karein. Eigenvectors ko unke eigenvalues ke hisaab se sort karein (sab se bari variance pehle), top k rakhein (misal ke tor par 2), unhein matrix W ki rows ki tarah lagayein, aur data ko naye axes par ghumayein:

Z = Xcentered · WT

Z is your reduced dataset: same rows, now only k columns (PC1, PC2, …), with PC1 holding the largest share of variance.

Z aapka reduced dataset hai: wohi rows, ab sirf k columns (PC1, PC2, …), aur PC1 ke paas variance ka sab se bara hissa hota hai.

Projection: dropping data onto a line or plane by a perpendicular "shadow" — geometrically, z = x · w is the length of x's shadow on direction w. PCA projects every point onto the top eigenvector directions, so each point's many numbers collapse into a few shadow-coordinates (its PC scores).
Projection: data ko kisi line ya plane par perpendicular "saaya" girana — geometrically, z = x · w woh lambai hai jo x ke saaye ki direction w par hoti hai. PCA har point ko top eigenvector directions par project karta hai, is liye har point ke bohat se numbers chand saaya-coordinates mein simat jaate hain (uske PC scores).
Explained variance ratio: for each component, its eigenvalue divided by the total of all eigenvalues — the fraction of the dataset's total variance (information) that this one component carries. In sklearn it is pca.explained_variance_ratio_; e.g. [0.92, 0.05] means PC1 holds 92% of the information and PC2 another 5%. You decide how many components to keep by adding these up (e.g. keep enough to pass 95%).
Explained variance ratio: har component ka apna eigenvalue tamam eigenvalues ke sum par divide hua — dataset ki total variance (information) ka woh hissa jo yeh aik component apne paas rakhta hai. sklearn mein yeh pca.explained_variance_ratio_ hai; misal ke tor par [0.92, 0.05] ka matlab PC1 ke paas 92% information hai aur PC2 ke paas aura 5%. Aap inhein jama kar ke tay karte hain ke kitne components rakhne hain (misal ke tor par itne rakhein ke 95% cross ho jaye).

Standardizing first (StandardScaler, which makes every feature mean 0 and std 1 — already explained in Core Concepts) is not optional decoration: PCA chases variance, so any feature measured in bigger units (petal length in cm vs a pixel 0–255) would dominate the components just because its numbers are bigger, not because it matters more.

Pehle standardize karna (StandardScaler, jo har feature ko mean 0 aur std 1 bana deta hai — Core Concepts mein already samjhaya gaya) koi ikhtiyari sajawat nahi: PCA variance ka peechha karta hai, to jo feature baray units mein napa gaya ho (petal length cm mein vs pixel 0–255) woh components par chhaa jayega — sirf is liye ke uske numbers bare hain, ye ke woh zyada ahem ho.

Diagram

Notice that the cloud is tilted: the crowd stretches most along the long arrow — that direction is PC1, the eigenvector with the biggest eigenvalue — and the short perpendicular arrow is PC2. If you kept only PC1 you'd lose just the thin spread of the shadow.

Dhyan dein ke cloud tircha hai: bheed sab se zyada lambi arrow ke saath phaili hui hai — wohi direction PC1 hai, sab se bare eigenvalue wala eigenvector — aur chhoti perpendicular arrow PC2 hai. Agar aap sirf PC1 rakhein to aapko sirf saaye ka patla phail khona parega.

Dataset (Kaggle)

uciml/iris via kagglehub → file Iris.csv. The classic Iris dataset, collected by Edgar Anderson and made famous by R.A. Fisher (1936): 150 iris flowers, each measured on 4 numeric features — sepal length, sepal width, petal length, petal width (all in cm) — plus a Species column with three balanced classes (50 each of Iris-setosa, Iris-versicolor, Iris-virginica) and an Id row-number column we drop. It's the perfect PCA demo: 4 features is too many to plot, but 2 PCs are enough to see the species separate.

uciml/iris kagglehub ke zariye → file Iris.csv. Classic Iris dataset, jise Edgar Anderson ne jama kiya aur R.A. Fisher (1936) ne mashhoor kiya: 150 iris ke phool, har phool par 4 numeric features — sepal length, sepal width, petal length, petal width (sab cm mein) — plus aik Species column jis mein teen balanced classes hain (Iris-setosa, Iris-versicolor, Iris-virginica — har aik 50) aur aik Id column jo sirf row number hota hai, hum usay drop kar dete hain. Yeh PCA ke liye behtareen demo hai: 4 features plot karne ke liye bohat zyada hain, lekin 2 PCs kaafi hain dekhne ke liye ke species alag ho rahe hain.

Practice code — run in Google Colab, top to bottom

Blocks must run in order. Copy each block into a Colab cell and run with Shift+Enter. kagglehub needs no API key for public datasets.
Blocks tarteeb se chalane hain. Har block ko Colab cell mein copy karein aur Shift+Enter se chalayein. Public datasets ke liye kagglehub ko kisi API key ki zaroorat nahi.
BLOCK 1: imports

Everything we need: pandas/numpy for data, kagglehub for the dataset, sklearn for scaling, PCA and Logistic Regression, matplotlib/seaborn for plots.

Jo kuch chahiye woh sab: pandas/numpy data ke liye, kagglehub dataset ke liye, sklearn scaling, PCA aur Logistic Regression ke liye, matplotlib/seaborn plots ke liye.

import glob                       # to find the downloaded CSV file path
import kagglehub                  # one-line Kaggle dataset download
import numpy as np                # matrix math (covariance, eigenvalues)
import pandas as pd               # tables (load Iris.csv, head, etc.)
import matplotlib.pyplot as plt   # scatter plots and heatmaps
import seaborn as sns             # prettier scatter/heatmap in one line
from sklearn.preprocessing import StandardScaler   # mean 0 / std 1 before PCA
from sklearn.decomposition import PCA              # the algorithm itself
from sklearn.linear_model import LogisticRegression  # to test the compressed features
from sklearn.model_selection import train_test_split  # fair comparison train/test
from sklearn.metrics import accuracy_score         # score the classifier
print("imports ok")
BLOCK 2: download the dataset with kagglehub

kagglehub pulls the public Iris dataset straight into Colab — no account, no manual upload.

kagglehub public Iris dataset seedha Colab mein le aata hai — na account chahiye, na manually upload karna parega.

# download uciml/iris and get the local folder path where it lives
path = kagglehub.dataset_download("uciml/iris")
print("dataset folder:", path)

# find Iris.csv inside that folder (glob searches by pattern)
csv_file = glob.glob(path + "/Iris.csv")[0]
print("csv file:", csv_file)
BLOCK 3: load and look at the data

Load the table, check its shape, and eyeball the first rows so we know the columns before touching them.

Table load karein, shape check karein, aur pehli rows nazar se dekh lein taake columns ko haath lagane se pehle hum unhein jaan lein.

df = pd.read_csv(csv_file)          # read the CSV into a DataFrame
print(df.shape)                     # (150, 6): 150 flowers, 6 columns (Id dropped in next block)
print(df["Species"].value_counts()) # 50 flowers per species — balanced classes
df.head()                           # first 5 rows: Id, 4 measurements, Species
BLOCK 4: clean — drop Id, split features from labels

Id is just a row number: it carries no information, and PCA would happily build a component out of it if we left it in. We keep X (4 measurements) and y (labels) apart because PCA may only ever see X.

Id sirf aik row number hai: is mein koi information nahi, aur agar hum ise chor dein to PCA khushi khushi is se bhi component bana leta. Hum X (4 measurements) aur y (labels) alag rakhte hain kyunke PCA ko sirf X dekhne ki ijazat hai.

df = df.drop(columns=["Id"])        # Id is a row index, not a real feature
X = df[["SepalLengthCm", "SepalWidthCm", "PetalLengthCm", "PetalWidthCm"]]
y = df["Species"]                   # labels kept OUT of PCA (it is unsupervised)
print(X.describe().round(2))        # means/stds differ per feature → must scale
BLOCK 5: standardize with StandardScaler

PCA hunts for variance, so we first force all 4 features to mean 0 and std 1 — otherwise the feature with the biggest raw numbers would hijack PC1. This is Step 1 of the math section, plus unit scaling.

PCA variance ka shikaar karta hai, is liye hum pehle 4 features ko mean 0 aur std 1 par la dete hain — warna jis feature ke raw numbers sab se bare hoten woh PC1 ko hijack kar leta. Yeh math section ka Step 1 hai, unit scaling ke saath.

scaler = StandardScaler()           # learns each column's mean and std
X_scaled = scaler.fit_transform(X)  # subtract mean, divide by std → centered data
print("column means after scaling:", np.round(X_scaled.mean(axis=0), 3))  # all ~0
print("column stds  after scaling:", np.round(X_scaled.std(axis=0), 3))   # all ~1
BLOCK 6: run PCA down to 2 components

fit_transform does the whole eigen-math pipeline on the scaled data — covariance matrix, eigenvalues/eigenvectors, sort, keep the top 2, project — and hands back 150 rows × 2 columns of PC scores.

fit_transform scaled data par poora eigen-math pipeline chala deta hai — covariance matrix, eigenvalues/eigenvectors, sort, top 2 rakhna, project — aur wapas 150 rows × 2 columns ke PC scores deta hai.

pca = PCA(n_components=2)           # keep only the top 2 directions (k = 2)
X_pca = pca.fit_transform(X_scaled) # fit finds the axes, transform projects points
print("before PCA:", X_scaled.shape)  # (150, 4)
print("after  PCA:", X_pca.shape)     # (150, 2) — 4 features compressed to 2
BLOCK 7: how much information did the 2 axes keep?

explained_variance_ratio_ is each eigenvalue's share of the total — the honest receipt for the compression. 0.92 + 0.05 = 0.97 would mean 97% of the variance survived.

explained_variance_ratio_ har eigenvalue ka total mein hissa hai — compression ka imaandar receipt. 0.92 + 0.05 = 0.97 ka matlab 97% variance bach gaya.

print("explained variance ratio:", pca.explained_variance_ratio_.round(4))
# PC1 keeps ~73.0%, PC2 ~22.9% → together ~95.8% of the original information (after StandardScaler)
print("total kept:", pca.explained_variance_ratio_.sum().round(4))

# quick bar chart: variance carried by each component
plt.bar(["PC1", "PC2"], pca.explained_variance_ratio_, color=["#4C72B0", "#DD8452"])
plt.ylabel("fraction of total variance")
plt.title("How much info each principal component keeps")
plt.show()
BLOCK 8: scatter PC1 vs PC2 colored by Species

The payoff plot: PCA never saw the labels, yet coloring the 2-D points by Species shows three clean groups — setosa fully separate, virginica/versicolor touching. This is exactly the picture K-Means and DBSCAN would cluster on.

Asal inaam wala plot: PCA ne labels kabhi nahi dekhe, phir bhi 2-D points ko Species ke rang se rangne par teen saaf groups nazar aate hain — setosa bilkul alag, virginica/versicolor aapas mein lagte hue. Yeh wohi manzar hai jis par K-Means aur DBSCAN cluster karte.

plt.figure(figsize=(7, 5))
for species, color in [("Iris-setosa", "#4C72B0"),
                       ("Iris-versicolor", "#DD8452"),
                       ("Iris-virginica", "#55A868")]:
    mask = (y == species)               # rows belonging to this species
    plt.scatter(X_pca[mask, 0], X_pca[mask, 1], label=species, color=color)
plt.xlabel("PC1 (73.0% variance)")      # PC1 score = projection on eigenvector 1
plt.ylabel("PC2 (22.9% variance)")       # PC2 score = projection on eigenvector 2
plt.legend()
plt.title("Iris in 2D — clusters appear WITHOUT labels")
plt.show()
# note: the three groups separated even though PCA is unsupervised;
# K-Means or DBSCAN could now cluster these 2 columns directly
BLOCK 9: inspect components_ — what is each PC made of?

components_ holds the eigenvectors (one per row). Its entries are the weights of each original feature, so you can read what PC1 "means".

components_ mein eigenvectors hote hain (har row mein aik). Is ki entries har original feature ke weights hain, is liye aap parh sakte hain ke PC1 ka "matlab" kya hai.

components_df = pd.DataFrame(
    pca.components_,                                    # 2 eigenvectors as rows
    columns=X.columns,                                  # weight per original feature
    index=["PC1", "PC2"])
print(components_df.round(3))
# PC1 ≈ equal weights on all 4 (a "overall size" axis, petal features heaviest)
# PC2 ≈ sepal width vs petal length in opposite signs (a "shape contrast" axis)
BLOCK 10: heatmap of the components

A heatmap makes the weights readable at a glance: strong color = that original feature matters a lot for that component; sign tells direction.

Heatmap weights ko aik nazar mein parhne layak bana deta hai: gehra rang = woh original feature us component ke liye bohat ahem hai; sign direction batata hai.

sns.heatmap(components_df, annot=True, cmap="coolwarm", center=0)
plt.title("Which original features each principal component uses")
plt.ylabel("principal component")
plt.xlabel("original feature")
plt.show()
BLOCK 11: the compression payoff — 2 PCs vs 4 originals

Train the same Logistic Regression twice: once on all 4 original (scaled) features, once on the 2 PCs. Nearly the same accuracy with half the features — that is the whole point of PCA.

Wohi Logistic Regression do dafa train karein: aik baar tamam 4 original (scaled) features par, aik baar 2 PCs par. Aadhe features ke bawajood taqreeban wohi accuracy — yahi PCA ka asal matlab hai.

# same split for both runs so the comparison is fair
X_train, X_test, y_train, y_test = train_test_split(
    X_scaled, y, test_size=0.3, random_state=42, stratify=y)

# run 1: full 4 standardized features
model_full = LogisticRegression(max_iter=1000)
model_full.fit(X_train, y_train)
acc_full = accuracy_score(y_test, model_full.predict(X_test))

# run 2: only the 2 PCA components (project FIRST, then split is also fine;
# here we project everything with one fitted PCA for simplicity)
X_train_pca = pca.transform(X_train)     # rotate train set onto the 2 axes
X_test_pca = pca.transform(X_test)       # rotate test set with the SAME axes
model_pca = LogisticRegression(max_iter=1000)
model_pca.fit(X_train_pca, y_train)
acc_pca = accuracy_score(y_test, model_pca.predict(X_test_pca))

print(f"accuracy with 4 original features: {acc_full:.3f}")
print(f"accuracy with 2 PCA components:    {acc_pca:.3f}")
# expect ~0.91 vs ~0.89 → same ballpark, half the features stored

Combining with other algorithms (project ideas)

PCA → K-Means. Run PCA to get PC1/PC2, then cluster the 2-D scores with K-Means (topic 08). Compare the clusters found to the true Species labels with a Confusion Matrix (topic 01) — you'll see unsupervised K-Means largely rediscovers the classes PCA revealed.

PCA → K-Means. PCA chala kar PC1/PC2 lein, phir 2-D scores par K-Means (topic 08) se cluster karein. Mile hue clusters ko asli Species labels se Confusion Matrix (topic 01) par compare karein — aap dekhenge ke unsupervised K-Means wohi classes dobara dhoond leta hai jo PCA ne samne laye the.

PCA → Logistic Regression / SVM pipeline. Compress with PCA, classify with Logistic Regression (topic 05) or SVM, and compare accuracy and training time against the raw features. This is Block 11 generalized, and the classic "reduce then classify" pattern for high-dimensional data.

PCA → Logistic Regression / SVM pipeline. PCA se compress karein, Logistic Regression (topic 05) ya SVM se classify karein, aur accuracy aur training time raw features se compare karein. Yeh Block 11 ki aam shakal hai, aur high-dimensional data ke liye classic "pehle reduce, phir classify" pattern.

PCA before any distance algorithm. K-Means and DBSCAN (topic 03) both rely on Euclidean distance, which gets unreliable in many dimensions (distances all blur together). Projecting to a few PCs first makes their distances meaningful — try DBSCAN on the 2 Iris PCs and watch it isolate setosa.

Har distance algorithm se pehle PCA. Pehle chand PCs par project karna unki distances ko maani banata hai — Iris ke 2 PCs par DBSCAN chala kar dekhein aur use setosa ko alag karte dekhein.

Interview Q&A

Q: What are the steps of PCA?
A: (1) Standardize/center each feature (mean 0, std 1). (2) Compute the covariance matrix of the features. (3) Solve the characteristic equation det(C − λI) = 0 to get the eigenvalues. (4) Find the eigenvectors — these are the principal axes. (5) Sort by eigenvalue descending and keep the top k. (6) Project the data onto those k axes: Z = X·WT. sklearn's PCA does all of this (via SVD) inside fit_transform.
Q: PCA ke steps kya hain?
A: (1) Har feature ko standardize/center karein (mean 0, std 1). (2) Features ka covariance matrix banayein. (3) Characteristic equation det(C − λI) = 0 solve kar ke eigenvalues nikaalein. (4) Eigenvectors dhoondein — yehi principal axes hain. (5) Eigenvalues ke hisaab se descending sort karein aur top k rakhein. (6) Data ko un k axes par project karein: Z = X·WT. sklearn ka PCA yeh sab fit_transform ke andar (SVD ke zariye) karta hai.
Q: Why standardize before PCA?
A: PCA maximizes variance, and variance is scale-dependent. A feature measured in larger units (salary in rupees vs age in years) has bigger variance and would dominate PC1 for no reason other than its units. StandardScaler puts every feature at mean 0, std 1 so each contributes fairly.
Q: PCA se pehle standardize kyun karte hain?
A: PCA variance ko maximize karta hai, aur variance scale par depend karti hai. Baray units mein napa gaya feature (salary rupees mein vs age saal mein) badi variance rakhta hai aur kisi wajah ke bagair — sirf apne units ki wajah se — PC1 par chhaa jata hai. StandardScaler har feature ko mean 0, std 1 par le aata hai taake har aik ka adal se hissa ho.
Q: PCA vs K-Means — both unsupervised, what's the difference?
A: PCA reduces dimensions: it builds new features (principal components) that summarize the data, but groups nothing. K-Means groups samples into k clusters using labels it invents. They answer different questions — "compress the columns" vs "group the rows" — and pair beautifully: PCA to 2-D, then K-Means on the PC scores.
Q: PCA vs K-Means — dono unsupervised hain, farq kya hai?
A: PCA dimensions kam karta hai: yeh nayi features (principal components) banata hai jo data ka khulasa rakhti hain, lekin kuch group nahi karta. K-Means samples ko k clusters mein baantta hai apne banaye hue labels se. Dono alag sawalon ke jawab hain — "columns ko compress karo" vs "rows ko group karo" — aur dono ki jori behtareen chalti hai: pehle 2-D tak PCA, phir PC scores par K-Means.
Q: What do the eigenvalues of the covariance matrix tell you in PCA?
A: Each eigenvalue is the amount of variance along its eigenvector's direction. Sorting eigenvalues descending ranks the directions; the ratio λi / Σλ (explained_variance_ratio_) is the share of total information component i carries.
Q: PCA mein covariance matrix ke eigenvalues aap ko kya batate hain?
A: Har eigenvalue apne eigenvector ki direction ke saath variance ki miqdaar hai. Eigenvalues ko descending sort karne se directions ka rank ban jaata hai; ratio λi / Σλ (explained_variance_ratio_) total information ka woh hissa hai jo component i apne paas rakhta hai.
Q: What is explained_variance_ratio_ and how do you use it to pick k?
A: It's each component's eigenvalue divided by the sum of all eigenvalues — the fraction of total variance it keeps. You pick k by cumulative sum: keep the smallest k whose ratios add up to a target like 95%. For Iris, 2 components already sum to ~95.8% (after StandardScaler).
Q: explained_variance_ratio_ kya hai aur k chunne ke liye kaise use hota hai?
A: Yeh har component ka apna eigenvalue tamam eigenvalues ke sum par divide hua hai — total variance ka woh hissa jo yeh rakhta hai. k cumulative sum se chuna jaata hai: sab se chhota k rakhein jis ke ratios kisi target jaise 95% tak pohanch jayein. Iris ke liye 2 components hi ~95.8% tak pohanch jaate hain (StandardScaler ke baad).
Q: Is PCA supervised or unsupervised? Does it use the target column?
A: Unsupervised — it never reads the labels. It only looks at how the input features spread (covariance). That's why species clusters "appearing" in the PC1/PC2 plot is meaningful: the labels were added for coloring only, after the fact.
Q: PCA supervised hai ya unsupervised? Kya yeh target column use karta hai?
A: Unsupervised — yeh labels kabhi nahi parhta. Yeh sirf dekhta hai ke input features kaise phaili hain (covariance). Isi liye PC1/PC2 plot mein species clusters ka "khud nazar aana" maani hai: labels sirf rang ke liye baad mein lagaye gaye the.
Q: Why is your teacher's point "SVM is totally opposite to PCA" right — and where do they still work together?
A: They're opposite in job: SVM is a supervised classifier that draws decision boundaries; PCA is an unsupervised reducer that compresses features and predicts nothing. But they chain well: PCA → SVM is a classic pipeline — compress to a few components so the SVM trains faster and its distance-based margin is less distorted by many noisy dimensions.
Q: Aapke teacher ka point "SVM is totally opposite to PCA" kyun sahi hai — aur yeh phir bhi saath kahan kaam karte hain?
A: Kaam ke lihaz se dono opposite hain: SVM supervised classifier hai jo decision boundaries khinchta hai; PCA unsupervised reducer hai jo features compress karta hai aur kuch predict nahi karta. Lekin dono ki zanjeer achi chalti hai: PCA → SVM classic pipeline hai — chand components tak compress karein taake SVM tez train ho aur uska distance-based margin bohat saare noisy dimensions se kharab na ho.
Q: What information does PCA lose, and when is that dangerous?
A: It keeps only the top-variance directions and discards the rest — low-variance features carrying the real signal get thrown away. If class separation lives in a small-variance direction (common in fraud or rare-detection tasks), PCA can hurt accuracy. Always validate downstream performance before/after, like our Block 11.
Q: PCA kya information kho deta hai, aur kab yeh khatarnak hota hai?
A: Yeh sirf top-variance directions rakhta hai aur baqi phenk deta hai — kam variance wali features jo asli signal rakhti hon woh bhi chali jaati hain. Agar class separation kisi chhoti-variance direction mein ho (fraud ya rare-detection kaamon mein aisa aam hai) to PCA accuracy gir sakta hai. Isi liye hamesha pehle/baad ka performance check karein, jaise hum ne Block 11 mein kiya.
Q: How would you use PCA with Logistic Regression on Iris, and what result do you expect?
A: Standardize, fit PCA(n_components=2), project, then train Logistic Regression on the 2 PCs and compare with the 4-feature model. On Iris they land around 91% and 89% accuracy — same ballpark with half the features stored, which is exactly the compression payoff PCA promises.
Q: Iris par aap PCA ko Logistic Regression ke saath kaise use karein ge, aur kya result expect karte hain?
A: Standardize karein, PCA(n_components=2) fit karein, project karein, phir 2 PCs par Logistic Regression train karein aur 4-feature model se compare karein. Iris par dono 91% aur 89% accuracy ke aas paas aate hain — taqreeban same performance, aadhe features — yehi PCA ka wada kiya hua compression inaam hai.
