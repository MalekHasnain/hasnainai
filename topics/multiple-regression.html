Multiple Linear Regression

Regression (supervised) Kaggle: House Price Regression scikit-learn

What it is (short intro)

Simple Linear Regression (Topic 06) predicts a number from one feature using a straight line. Real problems rarely have one cause: a house's price depends on size AND bedrooms AND age AND neighborhood together. Multiple Linear Regression extends the line to a plane (or hyperplane) that weighs many features at once.

It is the most interpretable predictive model in ML: after training you can literally read the equation and say "each extra bedroom adds $X to the price." That transparency is why banks, real-estate sites and economists still lean on it despite fancier models existing.

The math inside

y = b0 + b1x1 + b2x2 + … + b7x7
one weight per feature; the prediction is a weighted sum — in 3D this is a plane, in higher dimensions a hyperplane
Minimize Σ (actual − predicted)²
Ordinary Least Squares (OLS): the coefficients are chosen so the sum of squared residuals is as small as possible — solved by linear algebra in one shot. Residuals and OLS are explained in Core Concepts.
Multicollinearity: when two features are strongly correlated with each other (e.g. area and bedroom count), their coefficients become unstable and hard to interpret — the model can't decide which feature deserves the credit. Check with the correlation heatmap; PCA (Topic 07) or dropping one of the pair is the fix.
Adjusted R²: plain R² never goes down when you add features, even useless ones. Adjusted R² penalizes extra features, so it only rises when a new feature genuinely helps — the honest version for comparing models with different feature counts.

MAE, MSE, RMSE, R², train/test split and overfitting are already explained in Core Concepts.

Diagram

Notice: the green line passes through every training point (memorized) but will miss new points badly; the black line captures the general trend. We use this exact idea in Block 8 to catch overfitting via the train-vs-test R² gap.

Dataset (Kaggle)

House Price Regression (Home Value Insights) — 1,000 houses, each with 7 features (Square_Footage, Num_Bedrooms, Num_Bathrooms, Year_Built, Lot_Size, Garage_Size, Neighborhood_Quality 1-10) and one target: House_Price (continuous number → regression). All-numeric and clean, so you focus on the algorithm. Topic 06 used only Square_Footage from this same dataset — same data, one feature vs seven.

Practice code — run in Google Colab, top to bottom

Blocks must run in order — each block remembers the ones before it (same kernel session). Copy each block into Colab and run.
BLOCK 1: Imports

Load the libraries: tables, math, charts, the algorithm and the grading formulas.

import pandas as pd                    # tables (DataFrames)
import numpy as np                     # numerical math
import matplotlib.pyplot as plt        # charts
import seaborn as sns                  # heatmaps
from sklearn.model_selection import train_test_split   # hold out unseen test data
from sklearn.linear_model import LinearRegression      # the ML algorithm
from sklearn.metrics import mean_absolute_error, mean_squared_error, r2_score  # grading formulas
print("imports OK")
BLOCK 2: Download the dataset from Kaggle

kagglehub pulls the dataset straight into the notebook and prints the file path.

import kagglehub
path = kagglehub.dataset_download("prokshitha/home-value-insights")  # download + extract, returns folder path
print("dataset path:", path)                 # the file path where the data lives

import glob
csv_file = glob.glob(path + "/*.csv")[0]     # find the .csv inside the folder (name-independent)
print("csv file:", csv_file)
BLOCK 3: Load and look

Read the CSV, check the shape, glance at the first rows.

df = pd.read_csv(csv_file)                   # CSV -> DataFrame
print("shape:", df.shape)                    # (1000 rows, 8 columns)
df.head()                                    # first 5 rows
BLOCK 4: Correlation heatmap

Which features move with the price — and do any features move with each other (multicollinearity)?

plt.figure(figsize=(8, 6))                   # chart size
sns.heatmap(df.corr(numeric_only=True),      # Pearson r for every column pair (r = covariance / (std_x * std_y))
            annot=True, cmap="coolwarm", fmt=".2f")  # write numbers, red=+ blue=-
plt.title("Correlation heatmap — which features move with House_Price?")
plt.show()                                   # strong |r| with the target = useful predictor;
                                             # strong |r| BETWEEN features = multicollinearity warning
BLOCK 5: Separate X and y

Seven feature columns vs the single target column.

X = df[["Square_Footage", "Num_Bedrooms", "Num_Bathrooms", "Year_Built",
        "Lot_Size", "Garage_Size", "Neighborhood_Quality"]]  # double brackets = 7-column feature table
y = df["House_Price"]                        # single brackets = the one target column
print("X shape:", X.shape, "| y shape:", y.shape)   # (1000, 7) and (1000,)
BLOCK 6: Train/test split

Hide 20% for an honest grade — the anti-memorization move.

X_train, X_test, y_train, y_test = train_test_split(
    X, y, test_size=0.2,          # 20% held out
    random_state=42)              # frozen shuffle -> same split every run
print("train rows:", len(X_train), "| test rows:", len(X_test))   # 800 / 200
BLOCK 7: Train + read the equation

.fit() runs OLS; then print the learned equation — the model's actual "brain".

model = LinearRegression()        # empty model
model.fit(X_train, y_train)       # OLS: finds b0..b7 minimizing sum of (actual - predicted)^2

print("Intercept (b0):", round(model.intercept_, 2))     # predicted price when ALL features = 0 (base value)
for feature, coef in zip(X.columns, model.coef_):        # walk feature name + its weight in pairs
    print(f"{feature:25s} coefficient: {coef:,.2f}")     # +1 unit of this feature -> price changes by this many dollars
# interview line: "linear regression is interpretable — each coefficient is a dollar effect, sign included"
BLOCK 8: Predict + grade + overfitting check

Predict unseen houses, compute the four metrics, then the train-vs-test gap (the diagram above).

y_pred = model.predict(X_test)     # plug each test house's 7 features into the learned equation

mae  = mean_absolute_error(y_test, y_pred)   # average |error| in dollars
mse  = mean_squared_error(y_test, y_pred)    # average squared error (punishes big misses)
rmse = np.sqrt(mse)                          # back to dollar units
r2   = r2_score(y_test, y_pred)              # fraction of price variation explained
print(f"MAE : {mae:,.2f}")
print(f"RMSE: {rmse:,.2f}")
print(f"R2  : {r2:.4f}")

train_r2 = model.score(X_train, y_train)     # R2 on data the model HAS seen
test_r2  = model.score(X_test, y_test)       # R2 on data it NEVER saw
print(f"train R2: {train_r2:.4f} | test R2: {test_r2:.4f}")
print("gap:", round(train_r2 - test_r2, 4), "- small gap = healthy; big gap = overfitting")
BLOCK 9: Predict one new house

The production move: describe a house, get an instant price — exactly how Zillow-style estimates work.

new_house = pd.DataFrame({         # a 1-row table describing a new house
    "Square_Footage": [2500], "Num_Bedrooms": [4], "Num_Bathrooms": [3],
    "Year_Built": [2015], "Lot_Size": [0.5], "Garage_Size": [2],
    "Neighborhood_Quality": [8]})
price = model.predict(new_house)   # weighted sum: b0 + b1*size + ... + b7*quality
print(f"Predicted price: ${price[0]:,.2f}")
BLOCK 10: Residual plot (bonus diagnosis)

Errors should look like random noise around zero — a pattern means the linear form is wrong.

residuals = y_test - y_pred        # each unseen house's error (actual - predicted)
plt.figure(figsize=(7, 4))
plt.scatter(y_pred, residuals, alpha=0.5)            # x = predicted price, y = error; semi-transparent dots
plt.axhline(y=0, color="red", linestyle="--")       # the zero line = perfect prediction
plt.xlabel("Predicted price"); plt.ylabel("Residual (actual - predicted)")
plt.title("Residual plot — should be a random cloud around 0")
plt.show()                                           # curved/funnel shape = linear model is the wrong choice

Combining with other algorithms (project ideas)

1. Segment-then-predict. K-Means (Topic 08) splits customers/houses into segments, then you train one Multiple Linear Regression per segment — each segment gets its own equation, and total accuracy rises.

2. Beat multicollinearity with PCA. Topic 07 compresses correlated features into independent components; regress on the components instead of the raw features.

3. Regression + classification sandwich. Predict a house's price with this model, then Logistic Regression (Topic 05) predicts the yes/no question "will this listing sell within 30 days?" — number and event together.

Interview Q&A

Q1. Simple vs multiple linear regression?
Simple: one feature, a line (y = b0 + b1x). Multiple: two or more features, a plane/hyperplane (y = b0 + b1x1 + … + bnxn).
Q2. What does a coefficient mean?
The change in the target when that feature increases by exactly 1 unit, all other features held fixed. The sign gives the direction.
Q3. What does .fit() actually compute?
Ordinary Least Squares: the coefficients that minimize the sum of squared residuals — solved with linear algebra, not trial and error.
Q4. How do you detect overfitting here?
Compare train R² vs test R². A large gap means the model memorized. Fixes: more data, fewer features, regularization (Ridge/Lasso), cross-validation.
Q5. What is multicollinearity and why does it matter?
Strong correlation between features. It makes coefficients unstable and uninterpretable — detect with a correlation heatmap, fix by dropping a feature or applying PCA.
Q6. R² vs adjusted R²?
R² always rises when you add features, even junk ones; adjusted R² penalizes the feature count, so it only rises for genuinely useful features.
Q7. Why square the errors in OLS?
So positive and negative errors don't cancel, and so large errors are punished more than small ones.
Q8. Your residuals show a U-shaped curve — what does that mean?
The relationship isn't linear in the current features; add polynomial terms or use a non-linear model.
Q9. When would you switch from MLR to something else?
When relationships are non-linear, interactions dominate, or I need max accuracy over interpretability — e.g. gradient boosted trees; but I'd keep MLR as the baseline every model must beat.
