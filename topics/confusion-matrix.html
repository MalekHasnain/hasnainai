Confusion Matrix

Evaluation metric (classification) Kaggle: Breast Cancer Wisconsin scikit-learn

What it is (short intro)

A classifier predicts categories — sick/healthy, spam/not-spam. But how many of its predictions were right, and in which way were the mistakes made? The confusion matrix answers exactly that: a simple 2×2 (or n×n for more classes) table comparing what the model predicted against the truth.

It is called "confusing" because the mistakes reveal where the model gets confused. Every classification algorithm you will study — Logistic Regression, CNN, VGG16, RNN — is graded with this same table. That is why your teacher asked about it first: it is the report card of all classifiers.

Regression models (Topic 06, 09) do NOT use it — they predict continuous numbers and are graded with MAE/MSE/R² instead (Core Concepts).

The math inside

The four cells (for a yes/no problem, e.g. "malignant?"):

True Positive (TP): model said YES, truth is YES — correct catch.
True Negative (TN): model said NO, truth is NO — correct rejection.
False Positive (FP): model said YES, truth is NO — false alarm (Type I error).
False Negative (FN): model said NO, truth is YES — missed case (Type II error). In cancer detection this is the most dangerous cell.

From these four numbers, four ratios:

Accuracy = (TP + TN) / (TP + TN + FP + FN)
overall fraction of correct predictions
Precision = TP / (TP + FP)
of everything the model flagged, how much was truly positive — trustworthiness of an alarm
Recall (Sensitivity) = TP / (TP + FN)
of all true positives, how many the model caught — completeness of the sweep
F1 = 2 × (Precision × Recall) / (Precision + Recall)
one balanced number combining precision and recall (their harmonic mean)
When accuracy lies: if only 1% of transactions are fraud, a lazy model that always says "not fraud" scores 99% accuracy while catching ZERO fraud. With imbalanced data, always read precision/recall, not just accuracy. Our dataset is mildly imbalanced (357 benign vs 212 malignant) — good practice ground.

Train/test split, overfitting and other shared ideas are already explained in Core Concepts.

Diagram

Notice: rows = actual (truth), columns = predicted. The diagonal (TP, TN) is where the model is right; everything off-diagonal is a mistake, split into false alarms (FP) and missed cases (FN).

Dataset (Kaggle)

Breast Cancer Wisconsin Diagnostic — 569 tumor samples, 30 numeric measurements each (radius, texture, smoothness…) and one target: diagnosis (M = malignant, B = benign). Real medical data, perfectly clean, and the question "did we miss a malignant tumor?" makes precision/recall feel real. Target here is a category, so this is a classification problem.

Practice code — run in Google Colab, top to bottom

Blocks must run in order — each block remembers the ones before it (same kernel session). Copy each block into Colab and run.
BLOCK 1: Imports

Load the libraries: pandas for tables, sklearn for the model, metrics and the confusion matrix tools.

import pandas as pd                          # tables (DataFrames)
import numpy as np                           # numerical math
from sklearn.model_selection import train_test_split   # hold out unseen test data
from sklearn.linear_model import LogisticRegression    # the classifier engine (full detail in Topic 05)
from sklearn.metrics import (confusion_matrix, ConfusionMatrixDisplay,  # the star of this topic
                             accuracy_score, classification_report)
print("imports OK")
BLOCK 2: Download the dataset from Kaggle

kagglehub pulls the dataset straight into the notebook and prints the file path — no manual download, no API key needed.

import kagglehub                             # Kaggle dataset downloader
path = kagglehub.dataset_download("uciml/breast-cancer-wisconsin-data")  # download + extract, returns folder path
print("dataset path:", path)                 # the file path where the data lives

import glob
csv_file = glob.glob(path + "/*.csv")[0]     # find the .csv inside the folder (name-independent)
print("csv file:", csv_file)
BLOCK 3: Load and look

Read the CSV into a DataFrame and take a first look at shape and columns.

df = pd.read_csv(csv_file)                   # CSV -> DataFrame
print("shape:", df.shape)                    # (569 rows, 33 columns)
print(df.columns.tolist()[:8], "...")        # first few column names
df.head()                                    # first 5 rows
BLOCK 4: Separate features (X) and target (y)

The target is the diagnosis column; the 30 measurements are the features. The id column carries no signal and an empty "Unnamed: 32" column sometimes appears — both are dropped.

df = df.drop(columns=["id"], errors="ignore")          # id is just a row label, not a signal
df = df.drop(columns=[c for c in df.columns if c.startswith("Unnamed")], errors="ignore")  # drop stray empty columns
X = df.drop(columns=["diagnosis"])                     # all 30 numeric measurements = features
y = df["diagnosis"].map({"B": 0, "M": 1})              # target: map letters to 0 (benign) / 1 (malignant)
print("X shape:", X.shape, "| y positives:", y.sum())  # 569 rows, 30 features; 212 malignant
BLOCK 5: Train/test split

Hide 20% of the data so the matrix is computed on samples the model never saw — an honest evaluation.

X_train, X_test, y_train, y_test = train_test_split(
    X, y, test_size=0.2,           # 20% held out for testing
    random_state=42,               # frozen shuffle -> reproducible split
    stratify=y)                    # keep the same B/M ratio in train and test (fair for imbalanced data)
print("train:", len(X_train), "test:", len(X_test))
BLOCK 6: Train a classifier

Logistic Regression is just the engine here — full explanation in Topic 05. The job of this page is reading the matrix it produces.

model = LogisticRegression(max_iter=5000)    # create the classifier; max_iter raised so training fully converges
model.fit(X_train, y_train)                   # learn from 80% of the data
print("training done")
BLOCK 7: Predict

Predict the held-out 20% — these predictions vs the truth will fill the matrix.

y_pred = model.predict(X_test)               # predicted class (0/1) for each unseen sample
comparison = pd.DataFrame({"actual": y_test.values, "predicted": y_pred})
comparison.head(10)                           # eyeball a few rows first
BLOCK 8: THE CONFUSION MATRIX

The whole topic in one command: sklearn counts TP, FP, FN, TN for us.

cm = confusion_matrix(y_test, y_pred)        # counts the 4 cells: [[TN, FP], [FN, TP]]
print("Confusion matrix (rows = actual 0/1, columns = predicted 0/1):")
print(cm)
tn, fp, fn, tp = cm.ravel()                  # .ravel() unpacks the 2x2 grid into the four numbers
print(f"TN={tn}  FP={fp}  FN={fn}  TP={tp}")

ConfusionMatrixDisplay.from_predictions(y_test, y_pred)  # draws the colored matrix
plt_cm = None                                # display uses its own plot
BLOCK 9: Accuracy, precision, recall — the ratios

Turn the four counts into the four ratios, by hand AND with sklearn — see that they match.

# by hand (the math, visible):
acc_by_hand  = (tp + tn) / (tp + tn + fp + fn)     # Accuracy formula
prec_by_hand = tp / (tp + fp)                       # Precision formula
rec_by_hand  = tp / (tp + fn)                       # Recall formula
# by sklearn (the shortcut):
print(f"Accuracy  : {accuracy_score(y_test, y_pred):.4f} (hand: {acc_by_hand:.4f})")
print(f"Precision : {prec_by_hand:.4f}")
print(f"Recall    : {rec_by_hand:.4f}")
print(classification_report(y_test, y_pred, target_names=["benign", "malignant"]))  # all ratios per class + F1

Reading it like an interview answer: "Recall on the malignant class tells me what fraction of real tumors we caught; precision tells me how trustworthy a malignant flag is. In medicine, missing a tumor (FN) is worse than a false alarm (FP), so recall matters more."

Interview Q&A

Q1. What is a confusion matrix?
A table comparing predicted classes against actual classes for a classifier: TP, FP, FN, TN. From it come accuracy, precision, recall and F1.
Q2. Why is accuracy alone not enough?
With imbalanced classes accuracy can be high while the model catches zero positives — a fraud model that always says "not fraud" scores 99% accuracy. Precision and reveal what accuracy hides.
Q3. Precision vs recall — one line each?
Precision = of my alarms, how many were real (TP/(TP+FP)). Recall = of all real cases, how many I caught (TP/(TP+FN)).
Q4. Which is worse: FP or FN?
Problem-dependent. In cancer screening FN (missed disease) is worse; in spam filtering FP (lost real email) is worse. Choose the metric you optimize accordingly.
Q5. Where does the confusion matrix fit for CNN/VGG16 (image classifiers)?
Exactly the same place — after predicting test images, the matrix becomes num_classes × num_classes; for CIFAR-10 it is 10×10. The diagonal shows which image classes the net confuses.
Q6. Does linear regression use a confusion matrix?
No — regression predicts continuous numbers, so it is graded with MAE, MSE, RMSE and R². The confusion matrix belongs to classification only.
Q7. What is F1 score?
The harmonic mean of precision and recall — a single balanced number, useful when you need both high and classes are imbalanced.
Q8. What are Type I and Type II errors?
Type I = false positive (false alarm, FP). Type II = false negative (missed case, FN).
