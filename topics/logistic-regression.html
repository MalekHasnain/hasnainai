Logistic Regression

Classification Kaggle: yasserh/titanic-dataset scikit-learn pandas

What it is

Logistic regression answers a yes/no question with a probability. Instead of predicting a number like simple linear regression does, it predicts the chance that a sample belongs to class 1: the chance a passenger survives, an email is spam, a card transaction is fraud.

Logistic regression kisi yes/no sawal ka jawab probability ke saath deti hai. Koi number (jaise price) predict karne ke bajaye yeh kisi waqea ke hone ka chance batati hai.

The trick: take the exact same linear equation regression uses (b0 + b1x1 + … + bnxn), then push that score through the sigmoid function, which squashes any number into the range (0, 1). Now the output can be read as a probability. If the probability is 0.5 or higher, predict class 1; otherwise class 0. That 0.5 cut-off is the decision boundary.

Trick yeh hai: regression wali bilkul wohi linear equation lo.

Training works like every supervised model: it has labeled examples (each Titanic passenger is marked Survived 0 or 1), it makes predictions, measures how wrong it was with log loss, and nudges its coefficients to reduce that error. Unlike linear regression's squared-error loss, log loss punishes confident wrong predictions brutally — predicting 0.99 probability of survival for a passenger who died is heavily penalized.

Training har supervised model ki tarah chalti hai.

Despite the name, logistic regression is a classifier — one of the first you should learn, because it is fast, interpretable (you can read each coefficient as an effect on the odds), and it is literally the last layer of many neural networks. Here we train it on the Titanic dataset: predict which passengers survived, and finally read precision/recall from the confusion matrix — the payoff of Topic 01.

Naam ke bawajood (regression likha hai) yeh ek classifier hai.

The math inside

Logistic regression takes a linear combination of the features and passes it through the sigmoid to get a probability:

Logistic regression features ka linear combination banati hai aur sigmoid se guzaarti hai.

y = σ(b0 + b1x1 + b2x2 + … + bnxn)

The model computes the probability that the sample belongs to class 1, given its feature values.

Model nikalta hai probability ke namoona class 1 ka hai ya nahi.

σ(z) = 1 / (1 + e−z)

The sigmoid function — the S-curve that squashes any score z into (0, 1) — is already explained in Core Concepts.

Sigmoid function — woh S-curve jo kisi bhi score z ko (0, 1) mein daba deti hai — Core Concepts.

prediction = 1 if y ≥ 0.5, else 0

The decision rule: probability at or above 0.5 → class 1, below → class 0. At exactly 0.5 the sigmoid input z equals 0, which is the decision boundary.

Decision rule: probability 0.5 ya us se upar → class 1, neeche → class 0.

loss = log loss = −(1/n) Σ [ yi·log(pi) + (1−yi)·log(1−pi) ]

The training error being minimized — log loss (cross-entropy), which already lives in Core Concepts. Training finds the coefficients b that minimize it (via gradient descent at scale).

Jo training error minimize hota hai — log loss.

Odds: probability expressed as a ratio — odds = p/(1−p). If p = 0.8, the odds are 0.8/0.2 = 4, i.e. "4 to 1 in favor". Odds can run from 0 to infinity, unlike probability which is stuck in 0–1.
Odds ratio (how to read a logistic coefficient): for a coefficient bj, ebj is the multiplicative change in the odds when feature xj increases by 1 unit (other features fixed). bj = 0.47 → odds ratio e0.47 ≈ 1.6, meaning each extra unit of xj multiplies the odds of class 1 by ~1.6 (a 60% increase). A negative coefficient shrinks the odds. This is exactly why logistic regression is called interpretable.

Diagram

Notice the S-shape: hugely negative scores get squeezed toward 0, hugely positive ones toward 1, and the crossing point sits exactly at probability 0.5 where z = 0 — that is the decision boundary in action.

Dhyan do S-shape par: bara manfi score 0 ki taraf daba jata hai.

Dataset (Kaggle)

yasserh/titanic-dataset via kagglehub — file Titanic-Dataset.csv. The classic ML starter dataset: 891 passengers from the 1912 Titanic sinking, one row per passenger. Target column Survived (0 = died, 1 = survived). Features include Pclass (ticket class 1/2/3), Sex, Age, SibSp (siblings/spouses aboard), Parch (parents/children aboard), Fare, and Embarked (port C/Q/S). The Age column has missing values — which is perfect here, because this topic is where the SimpleImputer gets its moment (your notes: "imputer used to fill none value").

Practice code — run in Google Colab, top to bottom

Blocks must run in order. Copy each block into Colab exactly as shown; later blocks depend on earlier ones.
BLOCK 1: Imports

Everything the notebook needs, including SimpleImputer — the tool that fills missing Age values.

Notebook ko jo kuch chahiye, SimpleImputer samet.

# Import pandas for tables, numpy for math
import pandas as pd
import numpy as np

# kagglehub downloads the dataset straight into Colab
import kagglehub
import glob

# Model tools from scikit-learn
from sklearn.model_selection import train_test_split
from sklearn.pipeline import Pipeline
from sklearn.compose import ColumnTransformer
from sklearn.impute import SimpleImputer
from sklearn.linear_model import LogisticRegression
from sklearn.metrics import accuracy_score, confusion_matrix, classification_report
BLOCK 2: Download the dataset with kagglehub

Downloads the Titanic dataset into Colab and locates the CSV file inside the downloaded folder.

Titanic dataset Colab mein download.

# Download dataset 'yasserh/titanic-dataset' from Kaggle (needs no manual upload)
path = kagglehub.dataset_download("yasserh/titanic-dataset")

# kagglehub returns a folder — search it for the CSV file
csv_file = glob.glob(path + "/Titanic-Dataset.csv")[0]
print("Dataset file:", csv_file)
BLOCK 3: Load and look at the data

Read the CSV into a DataFrame and take a first look at rows and columns before any modeling.

CSV ko DataFrame mein parho aur pehli nazar daalo.

# Load the CSV into a pandas DataFrame
df = pd.read_csv(csv_file)

# Show the first 5 rows to understand the structure
print(df.head())

# Shape = (rows, columns) — 891 passengers
print("Shape:", df.shape)
BLOCK 4: Explore missing values

Count the empty cells per column — Age has gaps, which is exactly why we need the imputer.

Har column ki khali cells ginno.

# Count missing (None/NaN) values in every column
print(df.isnull().sum())

# You will see: Age ~177 missing, Cabin ~687, Embarked 2
# Age is a useful feature, so we will IMPUTE it instead of dropping rows
# Cabin is mostly empty, so we simply drop that column
BLOCK 5: Encode categorical features

Math needs numbers, so Sex becomes 0/1 and Embarked becomes 0/1/2 codes; we also drop columns we won't use.

Math ko numbers chahiye, is liye Sex 0/1 ban jata hai.

# Sex is text ('male'/'female') — map it to numbers the model can use
df['Sex'] = df['Sex'].map({'male': 0, 'female': 1})

# Embarked has 2 missing values — fill with the most common port, then encode C/Q/S as 0/1/2
df['Embarked'] = df['Embarked'].fillna(df['Embarked'].mode()[0])
df['Embarked'] = df['Embarked'].map({'C': 0, 'Q': 1, 'S': 2})

# Keep the useful numeric features; drop PassengerId, Name, Ticket (no signal) and Cabin (mostly missing)
features = ['Pclass', 'Sex', 'Age', 'SibSp', 'Parch', 'Fare', 'Embarked']
X = df[features]
y = df['Survived']  # target: 0 = did not survive, 1 = survived
print(X.head())
BLOCK 6: Build the pipeline with SimpleImputer (THE imputer block)

The imputer fills missing Age values (median) before the data reaches the model — "imputer used to fill none value". A ColumnTransformer applies the imputer only where needed and keeps everything in one pipeline.

Imputer missing Age values (median se) bhar deta hai data model tak puhanchne se pehle.

# Imputer used to fill none value: missing Age cells will be replaced by the column MEDIAN
# (median is safer than mean when Age is skewed by a few very old passengers)
imputer = SimpleImputer(strategy='median')

# ColumnTransformer applies the imputer to all 7 feature columns
preprocess = ColumnTransformer(
    transformers=[('impute', imputer, features)]  # fit learns each column's median
)

# Pipeline chains preprocessing + model: impute Age, then fit logistic regression
model = Pipeline(steps=[
    ('preprocess', preprocess),
    ('clf', LogisticRegression(max_iter=1000))  # max_iter raised so training fully converges
])
print(model)
BLOCK 7: Train/test split (stratified)

Hide 20% of passengers as a test set; stratify keeps the survived/died ratio identical in both parts.

20% passengers test set ke tor par chhupa do.

# Split: 80% train, 20% test; stratify=y keeps the 0/1 class balance in both sets
# random_state fixes the shuffle so results are reproducible
X_train, X_test, y_train, y_test = train_test_split(
    X, y, test_size=0.2, stratify=y, random_state=42
)
print("Train:", X_train.shape, " Test:", X_test.shape)
BLOCK 8: Train the model

Fit the pipeline: the imputer learns medians from training data, then logistic regression learns its coefficients.

Pipeline fit karo: imputer training data se median seekhta hai.

# fit: imputer fills missing Age with the train-set median,
# then LogisticRegression finds coefficients b0..b7 that minimize log loss
model.fit(X_train, y_train)
BLOCK 9: Predict — including the probability

predict gives the class 0/1; predict_proba shows the actual sigmoid probability behind each decision.

predict class 0/1 deta hai; predict_proba asli sigmoid probability dikhata hai.

# predict: applies the 0.5 decision boundary to each test passenger
y_pred = model.predict(X_test)

# predict_proba: the raw sigmoid output BEFORE the 0.5 cut — THE probability
# Column 0 = P(class 0), column 1 = P(class 1 = survived)
proba = model.predict_proba(X_test)

# Compare side by side for the first 5 passengers
compare = pd.DataFrame({
    'P(survive)': proba[:, 1].round(3),   # probability of class 1
    'predicted': y_pred,                  # 1 if P(survive) >= 0.5 else 0
    'actual': y_test.values
})
print(compare.head())
BLOCK 10: Evaluate — accuracy, confusion matrix, classification report

Topic 01 payoff: precision and recall per class from the confusion matrix tell a much better story than accuracy alone.

Topic 01 ka phal: confusion matrix se har class ka precision aur recall.

# Accuracy = share of correct predictions on the test set
print("Accuracy:", accuracy_score(y_test, y_pred))

# Confusion matrix: [[TN FP], [FN TP]] — read it like Topic 01 taught you
print("Confusion matrix:")
print(confusion_matrix(y_test, y_pred))

# Precision = TP/(TP+FP), recall = TP/(TP+FN), F1 = their harmonic mean
# Precision(of survived) = of all predicted survivors, how many really survived
# Recall(of survived) = of all actual survivors, how many we found
print(classification_report(y_test, y_pred, target_names=['Died (0)', 'Survived (1)']))
BLOCK 11: Predict one new passenger + read the coefficients as odds

Use the trained model on a made-up passenger, then interpret one coefficient as an odds ratio.

Trained model ko ek soch-samajh kar banaye passenger par chalao.

# A new passenger: 3rd class, male, 25, no family, cheap ticket, boarded at Southampton
new_passenger = pd.DataFrame(
    [[3, 0, 25.0, 0, 0, 7.25, 2]],
    columns=features  # same column order as training
)

# Full pipeline runs: imputer (no gaps here) then sigmoid -> probability
p_survive = model.predict_proba(new_passenger)[0, 1]
print(f"P(survive) = {p_survive:.3f} -> prediction: {'SURVIVES' if p_survive >= 0.5 else 'DOES NOT SURVIVE'}")

# Interpretability: coefficient on Sex, read as an odds ratio
clf = model.named_steps['clf']              # the trained LogisticRegression step
b_sex = clf.coef_[0][features.index('Sex')] # coefficient for Sex (0=male, 1=female)
print(f"Sex coefficient b = {b_sex:.3f}")
print(f"Odds ratio e^b = {np.exp(b_sex):.2f}: being female multiplies the survival ODDS by ~{np.exp(b_sex):.1f}x")
# Compare with the female 1st-class passenger below — same model, very different odds
new_passenger2 = pd.DataFrame([[1, 1, 30.0, 0, 0, 80.0, 2]], columns=features)
print(f"Female 1st-class P(survive) = {model.predict_proba(new_passenger2)[0, 1]:.3f}")

Fraud detectionPayPal and Stripe use logistic-style classifiers to score transactions as fraud probability in real time
Health issue check / risk scoringHospital risk models — e.g. heart-failure readmission scores — classically logistic regression on patient features

Combining with other algorithms (project ideas)

PCA → Logistic Regression. On wide data (hundreds of features), run PCA first to compress to the top components that carry most variance, then fit logistic regression on those scores. You fight overfitting and speed up training, at the cost of losing the clean odds interpretation.

PCA → Logistic Regression. Chauri data par.

K-Means segments + logistic per segment. Cluster customers with K-Means, then train a separate logistic churn model inside each segment — passengers in segment A and segment B can have different coefficients. Compare against DBSCAN: it also flags noise customers no cluster wants.

K-Means segments + har segment ka apna logistic. K-Means se customers cluster karo.

Logistic regression as the last layer of a neural network. A CNN like VGG16 ends with a softmax layer, which is exactly the multi-class generalization of sigmoid + log loss. Conceptually, VGG16 = feature extractor + logistic-style classifier bolted on top; an RNN classifier ends the same way.

Neural network ke aakhri layer ke tor par logistic regression.

Full evaluation wrap. Whatever the pipeline, grade it with the confusion matrix, precision/recall and cross-validation from Topic 01 and Core Concepts — accuracy alone hides class imbalance (as the Titanic data already shows: ~62% died).

Interview Q&A

Why is it called "regression" if it classifies?
Because under the hood it IS a regression: it fits the linear equation b0 + b1x1 + … + bnxn (it "regresses" the log-odds of the class onto the features). The sigmoid on top just maps that regression output into a probability, and the 0.5 threshold turns it into a classifier. The name predates the usage.
What does a coefficient mean in odds terms?
Coefficient ka matlab odds ki hasti mein kya hai?
For coefficient bj, ebj is the odds ratio: multiply the odds of class 1 by this factor for each one-unit increase in xj. bj > 0 pushes toward class 1, bj < 0 toward class 0. On Titanic, the Sex coefficient is large and positive — being female multiplies survival odds by several times.
Why is the sigmoid function needed at all?
The raw linear score can be any number from −∞ to +∞, but a probability must lie in (0, 1). The sigmoid squashes the score into that range while keeping order (bigger score → bigger probability), so the output can be read as P(class 1).
Why does logistic regression use log loss instead of mean squared error?
Two reasons: (1) squared error on a sigmoid output is non-convex — gradient descent can get stuck in local minima; log loss is convex, so there is one clean minimum. (2) Log loss punishes confident wrong predictions hard (predicting 0.99 for a passenger who died), which pushes calibrated probabilities.
Does the 0.5 threshold always have to be 0.5?
No — 0.5 is just the default. For fraud detection you might predict "fraud" already at 0.2 because a missed fraud (recall) costs far more than a false alarm (precision). Move the threshold by using predict_proba and comparing against your own cut-off; the confusion matrix changes accordingly.
What happens if you feed missing values straight to the model?
scikit-learn raises an error (NaN/None not accepted). You must impute — e.g. SimpleImputer(strategy='median') fills each missing Age with the column median — or drop rows/columns. Fitting the imputer on training data only (which a Pipeline does automatically) avoids test-set leakage.
Why did we pass stratify=y in the train/test split?
Random splits can accidentally shift the class balance (e.g. test set 70/30 died/survived while the full data is 62/38). stratify=y forces both train and test to keep the original class ratio, so evaluation reflects reality.
How is logistic regression different from simple linear regression (Topic 06)?
Same linear core, different target and loss: simple linear regression predicts a continuous number with squared-error loss; logistic regression predicts class probability with a sigmoid output and log loss. Linear regression would happily output "survival = -0.3 or 2.7", which is meaningless for a 0/1 outcome — the sigmoid and 0.5 boundary fix that.
When would you pick logistic regression over a neural network?
When you need interpretability (regulators demand readable coefficients in credit scoring), have tabular data with few features, need a fast baseline, or have limited data/compute. Neural networks (CNN for images, RNN for sequences) win when the pattern is not linear in the raw features — but note even they typically end in a sigmoid/softmax + log loss layer, which IS logistic regression.
