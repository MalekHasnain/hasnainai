VGG16

Neural network Pre-trained CNN / Transfer learning Dataset: CIFAR-10 (Kaggle: pankrzysiu/cifar10-python) Library: tensorflow.keras

What it is

VGG16 is a convolutional neural network architecture published in 2014 by the Visual Geometry Group at Oxford. The "16" counts its weight layers: 13 convolutional layers plus 3 fully-connected (dense) layers at the end. It finished runner-up in the 2014 ImageNet challenge, and its trained weights became one of the most reused artifacts in deep learning.

What made VGG16 a breakthrough was not complexity but simplicity. Every single convolution in the network uses a tiny 3×3 filter. Instead of one big 7×7 filter, VGG stacks small ones: three 3×3 convolutions in a row see the same area as one 7×7 filter, but with fewer parameters and more non-linear steps in between. The whole network is just "conv, conv, pool" repeated with more and more filters — a pattern a beginner can read top to bottom (see Topic 02 — CNN for how convolution and pooling work).

The reason you still learn VGG16 in 2026 is transfer learning. Training VGG16 from scratch on ImageNet's 1.4 million images took weeks of GPU time, but the downloaded weights are free. The early layers learned generic visual features — edges, corners, textures — and those features are useful for almost any image task. So instead of training a giant network on your small dataset, you freeze the learned layers and train only a small classifier on top. You get ImageNet-quality vision with minutes of training.

In this topic we load VGG16 with ImageNet weights, freeze it, bolt on a small 10-class head, and teach it CIFAR-10 — the same dataset you classified with a hand-built CNN in Topic 02, so you can directly compare how much the transferred features buy you.

The math inside

VGG16 has no exotic math — convolution, pooling, ReLU and softmax, all already explained in Core Concepts (softmax also covered in Topic 02). The interesting math is in how the layers compose.

layers(VGG16) = 13 conv + 3 dense = 16 weight layers
all conv filters = 3×3, stride 1   |   all max-pools = 2×2, stride 2
Counts the architecture: 13 convolutions and 3 dense layers, every filter a small 3×3 window.
receptive field: 2 × (3×3) ≈ 5×5   |   3 × (3×3) ≈ 7×7
params: stacked 3×3 = 2 × (3²·C²) < 5²·C²
Stacking two or three small 3×3 convolutions covers the same pixels as one 5×5 or 7×7 filter, with fewer parameters and extra non-linearities in between.
outputspatial = ⌊(W − F)/S⌋ + 1  →  each 2×2 pool halves W,H while filters double: 64→128→256→512
Each convolution keeps the spatial size (F=3, S=1, padding=same) and each pool halves it; channel count doubles at every block, so the network trades where for what.
ŷ = softmax(Whead · pooled features + bhead)
In transfer learning we only train this head: the frozen VGG16 produces a 512-number feature vector, and our new dense layer turns it into class probabilities (log loss / cross-entropy as in Core Concepts).
Pre-trained weights — the parameter values (all the filter numbers) a network learned on a big dataset, saved to disk. weights="imagenet" downloads the values Oxford's VGG16 learned on ImageNet; without it the filters start as random numbers.
Transfer learning — reusing a model trained on task A as the starting point for task B. It works because early conv layers learn generic features (edges, textures, shapes) that transfer across image datasets, so only task-specific layers need training.
Feature extraction vs fine-tuning — two transfer-learning modes. Feature extraction: freeze the whole base, train only the new head (what we do below — safest for small datasets). Fine-tuning: after the head works, unfreeze the last few conv layers and re-train them with a very small learning rate so they specialise to your data.
Fully-connected head — the classifier stacked on top of the convolutional base: flatten (or pool) the final feature maps into one vector, then dense layers ending in a softmax. The original VGG16 head has 1000 ImageNet outputs; we throw it away (include_top=False) and grow our own with however many classes our task needs.

Diagram

Notice the rhythm: convolution blocks (in red) with more and more channels, each cut by a max-pooling layer (blue) that halves height and width, ending in the fully-connected head — exactly the conv/pool mechanics from Topic 02, just deeper and more regular.

Dataset (Kaggle)

CIFAR-10 — same dataset as Topic 02. Kaggle version: pankrzysiu/cifar10-python (kagglehub slug). 60,000 32×32 colour images in 10 classes (airplane, automobile, bird, cat, deer, dog, frog, horse, ship, truck) — 50,000 train / 10,000 test, 6,000 images per class. Each image is a 32×32×3 pixel tensor and the target is one of 10 labels. In Colab we skip the download entirely: keras.datasets.cifar10.load_data() fetches the identical dataset in one line.

Practice code — run in Google Colab, top to bottom

Blocks must run in order. Copy each block into a Colab cell (Runtime → Change runtime type → T4 GPU makes blocks 6–7 much faster) and run them one by one. We use a 5000-image subset so the whole notebook finishes in minutes on free Colab.
BLOCK 1: Imports

Everything we need: Keras for building models, the pre-built VGG16, and sklearn metrics for evaluation.

# TensorFlow's Keras API: model building, layers, and the VGG16 model itself
from tensorflow.keras.applications import VGG16
from tensorflow.keras.applications.vgg16 import preprocess_input
from tensorflow.keras import layers, models
# Pre-trained VGG16 weights are downloaded from a public Keras mirror (no login needed)
import tensorflow as tf
import numpy as np
import matplotlib.pyplot as plt
from sklearn.metrics import confusion_matrix, ConfusionMatrixDisplay, classification_report
BLOCK 2: Load a CIFAR-10 subset

CIFAR-10 is built into Keras, so loading it is one call. We keep the first 5000 train / 1000 test images so free Colab finishes quickly — classes stay because the data is pre-shuffled.

# CIFAR-10 ships inside Keras, so one call downloads the ready-made train/test split
# (same dataset as Topic 02: 60000 32x32 colour images, 10 classes)
from tensorflow.keras.datasets import cifar10
(X_train_full, y_train_full), (X_test_full, y_test_full) = cifar10.load_data()

# Free Colab is slow, so keep only a subset: first 5000 train / 1000 test images
# Classes are already shuffled, so a slice keeps all 10 labels balanced enough
X_train_raw, y_train = X_train_full[:5000], y_train_full[:5000]
X_test_raw,  y_test  = X_test_full[:1000],  y_test_full[:1000]

# Labels come as a column vector -> flatten to a 1-D array of class ids 0..9
y_train, y_test = y_train.ravel(), y_test.ravel()

# The 10 class names, in label order (airplane=0 ... truck=9)
class_names = ["airplane","automobile","bird","cat","deer",
               "dog","frog","horse","ship","truck"]
print("Train subset:", X_train_raw.shape, "Test subset:", X_test_raw.shape)
BLOCK 3: Resize + ImageNet preprocessing

VGG16 needs its input preprocessed exactly the way ImageNet images were when the weights were learned — otherwise the transferred features see numbers they don't recognise. We also upscale 32×32 → 48×48 so the deep pooling stack doesn't shrink the image to nothing.

# VGG16 refuses inputs smaller than 32x32; we upscale 32->48 so early pooling
# still leaves enough pixels for the deep stack of convolutions
X_train = tf.image.resize(X_train_raw, (48, 48)).numpy()
X_test  = tf.image.resize(X_test_raw,  (48, 48)).numpy()

# VGG16-specific preprocessing: RGB->BGR then zero-centre each channel
# using the ImageNet means the pre-trained weights were trained with
X_train = preprocess_input(X_train)
X_test  = preprocess_input(X_test)
print("After resize + preprocess:", X_train.shape, X_test.shape)
BLOCK 4: Load VGG16 with ImageNet weights and freeze it

This is the transfer-learning moment: weights="imagenet" loads the features Oxford learned from 1.4M images, include_top=False throws away their 1000-class head, and freezing protects those features from our small dataset's noisy gradients.

# Load VGG16 WITHOUT its 1000-class ImageNet head but WITH learned ImageNet weights
# weights="imagenet" is the transfer-learning switch: it loads the filters the
# Oxford group learned from 1.4M images instead of starting from random numbers
base = VGG16(weights="imagenet", include_top=False, input_shape=(48, 48, 3))

# Freeze the base: set every weight to non-trainable
# Why: with only 5000 images we would overwrite (destroy) the general ImageNet
# features if our small dataset pushed big gradient updates into the base
base.trainable = False
base.summary()
BLOCK 5: Add our own classifier head

The frozen base ends with 3×3×512 feature maps; we pool them to a 512-number vector and learn a small dense classifier on top — the only part that trains.

# Build a small "head": our own classifier that sits on top of the frozen base
model = models.Sequential([
    base,                                        # frozen VGG16 feature extractor
    layers.GlobalAveragePooling2D(),             # average each 3x3x512 feature map -> 512 numbers
    layers.Dense(128, activation="relu"),        # small fully-connected layer to recombine features
    layers.Dropout(0.3),                         # randomly zero 30% of activations to fight overfitting
    layers.Dense(10, activation="softmax")       # 10 outputs = CIFAR-10 class probabilities
])
model.summary()
BLOCK 6: Compile and train (head only)

Only ~170k head parameters train — the 14.7M base weights sit still. Three epochs on 5000 images is enough to see transfer learning work.

# Compile: adam optimizer, sparse categorical cross-entropy (labels are ints, not one-hot)
model.compile(optimizer="adam",
              loss="sparse_categorical_crossentropy",
              metrics=["accuracy"])

# Train only the ~170k head weights (the 14.7M base weights stay frozen)
# 3 epochs x 125 steps keeps the run under ~10 minutes on a free Colab GPU
history = model.fit(X_train, y_train,
                    epochs=3,
                    batch_size=40,
                    validation_split=0.15,
                    verbose=1)
BLOCK 7: Evaluate + confusion matrix

Accuracy on the held-out 1000 images, then the confusion matrix (Topic 01) to see which classes the transferred features still confuse — usually cats vs dogs.

# Evaluate on the held-out 1000 test images
test_loss, test_acc = model.evaluate(X_test, y_test, verbose=0)
print(f"Test accuracy: {test_acc:.3f}")

# Confusion matrix (Topic 01): which classes get confused with which
y_pred = model.predict(X_test, verbose=0).argmax(axis=1)   # argmax picks the top class
cm = confusion_matrix(y_test, y_pred)
disp = ConfusionMatrixDisplay(cm, display_labels=class_names)
fig, ax = plt.subplots(figsize=(9, 9))
disp.plot(ax=ax, xticks_rotation=45, cmap="Blues", colorbar=False)
plt.title("VGG16 transfer learning - CIFAR-10 (subset)")
plt.tight_layout()
plt.show()

# Per-class precision / recall / F1 to spot weak classes
print(classification_report(y_test, y_pred, target_names=class_names))
BLOCK 8: Predict one image

Use the finished model like a product: show one test image and print the model's ranked class probabilities.

# Pick one test image and predict it, showing the model's confidence
i = 12
prob = model.predict(X_test[i:i+1], verbose=0)[0]     # softmax over 10 classes
rank = prob.argsort()[::-1]                           # class ids sorted best to worst

plt.imshow(X_test_raw[i])
plt.title(f"True: {class_names[y_test[i]]}")
plt.axis("off")
plt.show()

for c in rank[:3]:
    print(f"{class_names[c]:12s} {prob[c]*100:5.1f}%")
BLOCK 9: Export VGG16 embeddings for other algorithms

The frozen base is also a feature extractor: any image becomes a 512-dim vector. These embeddings are the raw material for the combos below — SVM classification, K-Means grouping, PCA compression.

# Feature extraction mode: throw away the head, keep the 512-dim VGG16 embedding
# These vectors are reusable input for OTHER algorithms (SVM, K-Means, PCA)
features = base.predict(X_test[:500], verbose=0)
print("Embedding shape:", features.shape)   # (500, 3, 3, 512) before pooling
flat = features.reshape(features.shape[0], -1)
print("Flattened for SVM / K-Means:", flat.shape)   # (500, 4608)

Real-world use cases & companies

Use caseWho / example
Image search & visual similarityReverse image search engines use pre-trained CNN embeddings (the VGG family pioneered this) to find visually similar images — e.g. Pinterest visual search and eBay image-based listing search.
Medical imaging with small datasetsHospital research teams routinely fine-tune ImageNet CNNs like VGG16 on hundreds (not millions) of X-ray / MRI scans, because transfer learning is the only way small clinical datasets reach usable accuracy.
Agriculture disease detectionAgri-tech startups (e.g. Plantix) classify crop-disease photos from farmers' phones using transfer-learned CNNs — VGG16 remains a standard baseline in plant-disease literature.
Face recognition pipelinesDeepFace (Facebook's face-verification system) used a VGG-style deep CNN to map faces to vectors and decide if two photos show the same person.
Pre-built vision features as a serviceGoogle Cloud Vision and AWS Rekognition embody the same idea: one giant pre-trained model, everyone else transfers its features to their own task.

VGG16 + K-Means: unsupervised image grouping. Forget the labels entirely: embed 1000 images with the frozen base, reduce with PCA (Topic 07) to ~50 dims, then cluster with K-Means (Topic 08) (k=10). VGG16 + RNN: image captioning. Keep the frozen base as the "eye", feed its 512-dim feature vector into the RNN (Topic 10) as the "mouth" that generates a word-by-word caption. This encoder-decoder pattern is exactly how classic captioning systems like Show and Tell worked.

Interview Q&A

What is transfer learning and why does it work?
Transfer learning reuses a model trained on one task (source) as the starting point for another (target). It works because early convolutional layers learn generic visual features — edges, corners, textures — that are useful for nearly any image dataset, so only the task-specific top layers need retraining. It turns a weeks-long, million-image training job into minutes on a small dataset.
Why does VGG16 use only 3×3 filters?
Stacking three 3×3 convolutions covers the same receptive field as one 7×7 filter but with fewer parameters (2·3²C² < 7²C² per layer comparison) and — crucially — two extra ReLU non-linearities in between, letting the network learn more complex functions. It also made the architecture uniform and simple to reason about, which was itself the paper's point.
What do weights="imagenet" and include_top=False each do?
weights="imagenet" loads the parameters trained on ImageNet instead of random initialisation — the transfer-learning switch. include_top=False drops the final dense layers that output 1000 ImageNet classes, so we can attach our own head with however many outputs our task needs (10 for CIFAR-10).
Why do we set base.trainable = False instead of training everything?
With a small dataset, gradients from a few thousand images are noisy and would overwrite the general features the base learned from 1.4M images — catastrophic forgetting on a budget. Freezing the base means only our small head trains: fewer parameters, faster epochs, and much less overfitting. Once the head converges, fine-tuning can cautiously unfreeze the last blocks with a tiny learning rate.
What is the difference between feature extraction and fine-tuning?
Both start from frozen pre-trained weights plus a new head. Feature extraction keeps the base permanently frozen and only trains the head (or skips the head and feeds the embeddings to a classic model like an SVM). Fine-tuning unfreezes some or all base layers after initial training and continues with a very small learning rate so the base specialises to the new data without destroying what it knew.
Why did we resize CIFAR-10 images and run preprocess_input on them?
The pre-trained weights expect inputs in the same numeric regime as ImageNet training: VGG16's preprocess_input converts RGB to BGR and zero-centres channels with ImageNet means. Feeding raw 0–255 RGB pixels would make the transferred filters see out-of-distribution values and the features would degrade. The resize to 48×48 (from 32×32) keeps enough spatial resolution for the five 2×2 pooling layers.
VGG16 is ~138M parameters — why is it considered "simple"?
Simple refers to architecture, not size. VGG16 is one repeated pattern — 3×3 convolutions, same padding, 2×2 max-pool, doubling channels — with no branches, no exotic layers, no special tricks. That uniformity is why it became the default teaching and transfer-learning backbone, even though later nets (ResNet etc.) beat it with far fewer parameters.
How does VGG16 relate to the CNN you built in Topic 02?
Same machinery, different scale and origin. Your Topic 02 CNN is a small network you trained from scratch: random filters slowly learning edges for CIFAR-10. VGG16 is that same conv/pool/softmax pattern repeated 13 convolutions deep, with filters already trained on ImageNet — comparing the two on the same data quantifies exactly what transfer learning adds.
