VGG16

Neural network Neural network Pre-trained CNN / Transfer learning Pre-trained CNN / Transfer learning Dataset: CIFAR-10 (Kaggle: pankrzysiu/cifar10-python) Dataset: CIFAR-10 (Kaggle: pankrzysiu/cifar10-python) Library: tensorflow.keras Library: tensorflow.keras

What it is

VGG16 is a convolutional neural network architecture published in 2014 by the Visual Geometry Group at Oxford. The "16" counts its weight layers: 13 convolutional layers plus 3 fully-connected (dense) layers at the end. It finished runner-up in the 2014 ImageNet challenge, and its trained weights became one of the most reused artifacts in deep learning.

VGG16 ek convolutional neural network architecture hai jo 2014 mein Oxford ke Visual Geometry Group ne publish ki. Iska "16" iske weight layers ginta hai: 13 convolutional layers aur aakhir mein 3 fully-connected (dense) layers. Yeh 2014 ke ImageNet challenge mein runner-up rahi, aur iske trained weights deep learning ke sab se zyada reuse hone wale artifacts mein se ek ban gaye.

What made VGG16 a breakthrough was not complexity but simplicity. Every single convolution in the network uses a tiny 3×3 filter. Instead of one big 7×7 filter, VGG stacks small ones: three 3×3 convolutions in a row see the same area as one 7×7 filter, but with fewer parameters and more non-linear steps in between. The whole network is just "conv, conv, pool" repeated with more and more filters — a pattern a beginner can read top to bottom (see Topic 02 — CNN for how convolution and pooling work).

VGG16 ko breakthrough banaya complexity nahi balkay simplicity ne. Network ka har single convolution ek chhota 3×3 filter use karta hai. Ek bare 7×7 filter ke bajaye VGG chhote filters stack karta hai: lagatar teen 3×3 convolutions wahi area dekhte hain jo ek 7×7 filter, lekin kam parameters aur beech mein zyada non-linear steps ke saath. Pura network bas "conv, conv, pool" ka repetition hai har baar aur zyada filters ke saath — aisi pattern jo koi beginner bhi top se bottom tak parh sake (convolution aur pooling kaise kaam karti hain, is ke liye Topic 02 — CNN dekhein).

The reason you still learn VGG16 in 2026 is transfer learning. Training VGG16 from scratch on ImageNet's 1.4 million images took weeks of GPU time, but the downloaded weights are free. The early layers learned generic visual features — edges, corners, textures — and those features are useful for almost any image task. So instead of training a giant network on your small dataset, you freeze the learned layers and train only a small classifier on top. You get ImageNet-quality vision with minutes of training.

2026 mein aap VGG16 is liye seekhte hain ke transfer learning. ImageNet ke 1.4 million images par VGG16 ko scratch se train karne mein hafton ka GPU time lagta tha, lekin downloaded weights free hain. Early layers ne generic visual features seekhe — edges, corners, textures — aur woh features taqreeban har image task ke liye useful hain. Toh apne chhotay dataset par giant network train karne ke bajaye, learned layers ko freeze kar dein aur sirf upar ek chhota classifier train karein. Minutes ki training mein ImageNet-quality vision mil jati hai.

In this topic we load VGG16 with ImageNet weights, freeze it, bolt on a small 10-class head, and teach it CIFAR-10 — the same dataset you classified with a hand-built CNN in Topic 02, so you can directly compare how much the transferred features buy you.

Is topic mein hum VGG16 ko ImageNet weights ke saath load karenge, freeze karenge, upar ek chhota 10-class head lagayenge, aur usay CIFAR-10 par sikhayenge — wohi dataset jo aap ne Topic 02 mein hand-built CNN se classify kiya tha, taake aap seedha compare kar sakein ke transferred features aap ko kitna faida dete hain.

The math inside

VGG16 has no exotic math — convolution, pooling, ReLU and softmax, all already explained in Core Concepts (softmax also covered in Topic 02). The interesting math is in how the layers compose.

VGG16 mein koi exotic math nahi — convolution, pooling, ReLU aur softmax, sab kuch Core Concepts mein already explained hai (softmax Topic 02 mein bhi covered hai). Interesting math yeh hai ke layers aapas mein kaise compose hoti hain.

layers(VGG16) = 13 conv + 3 dense = 16 weight layers
all conv filters = 3×3, stride 1   |   all max-pools = 2×2, stride 2
Counts the architecture: 13 convolutions and 3 dense layers, every filter a small 3×3 window.
Architecture ka hisaab: 13 convolutions aur 3 dense layers, har filter ek chhota 3×3 window.
receptive field: 2 × (3×3) ≈ 5×5   |   3 × (3×3) ≈ 7×7
params: stacked 3×3 = 2 × (3²·C²) < 5²·C²
Stacking two or three small 3×3 convolutions covers the same pixels as one 5×5 or 7×7 filter, with fewer parameters and extra non-linearities in between.
Do ya teen chhote 3×3 convolutions stack karne se utne hi pixels cover hote hain jitna ek 5×5 ya 7×7 filter, lekin kam parameters aur beech mein extra non-linearities ke saath.
outputspatial = ⌊(W − F)/S⌋ + 1  →  each 2×2 pool halves W,H while filters double: 64→128→256→512
Each convolution keeps the spatial size (F=3, S=1, padding=same) and each pool halves it; channel count doubles at every block, so the network trades where for what.
Har convolution spatial size qayam rakhta hai (F=3, S=1, padding=same) aur har pool usay aadha kar deta hai; har block par channel count double hota hai, toh network kahan ki jagah kya seekh leti hai.
ŷ = softmax(Whead · pooled features + bhead)
In transfer learning we only train this head: the frozen VGG16 produces a 512-number feature vector, and our new dense layer turns it into class probabilities (log loss / cross-entropy as in Core Concepts).
Transfer learning mein hum sirf yeh head train karte hain: frozen VGG16 ek 512-number feature vector banati hai, aur hamari nayi dense layer usay class probabilities mein badal deti hai (log loss / cross-entropy jaise Core Concepts mein hai).
Pre-trained weights — the parameter values (all the filter numbers) a network learned on a big dataset, saved to disk. weights="imagenet" downloads the values Oxford's VGG16 learned on ImageNet; without it the filters start as random numbers.
Pre-trained weights — woh parameter values (saare filter numbers) jo koi network kisi bare dataset par seekh kar disk par save karta hai. weights="imagenet" Oxford ki VGG16 ke ImageNet par seekhe hue values download karta hai; iske baghair filters random numbers se shuru hote hain.
Transfer learning — reusing a model trained on task A as the starting point for task B. It works because early conv layers learn generic features (edges, textures, shapes) that transfer across image datasets, so only task-specific layers need training.
Transfer learning — task A par trained model ko task B ke starting point ke tor par dobara use karna. Yeh is liye kaam karta hai kyunki early conv layers generic features (edges, textures, shapes) seekhti hain jo image datasets ke darmiyan transfer ho jati hain, is liye sirf task-specific layers ko training chahiye hoti hai.
Feature extraction vs fine-tuning — two transfer-learning modes. Feature extraction: freeze the whole base, train only the new head (what we do below — safest for small datasets). Fine-tuning: after the head works, unfreeze the last few conv layers and re-train them with a very small learning rate so they specialise to your data.
Feature extraction vs fine-tuning — transfer learning ke do modes. Feature extraction: pura base freeze, sirf naya head train (jo hum neeche karte hain — chhote datasets ke liye sab se safe). Fine-tuning: jab head kaam karne lage, aakhri kuch conv layers unfreeze kar ke bohat chhotay learning rate se dobara train karna taake woh apne data ke mutabiq specialise ho jayein.
Fully-connected head — the classifier stacked on top of the convolutional base: flatten (or pool) the final feature maps into one vector, then dense layers ending in a softmax. The original VGG16 head has 1000 ImageNet outputs; we throw it away (include_top=False) and grow our own with however many classes our task needs.
Fully-connected head — convolutional base ke upar lagaya gaya classifier: final feature maps ko flatten (ya pool) kar ke ek vector banayein, phir dense layers jo softmax par khatam hon. Original VGG16 head mein 1000 ImageNet outputs hain; hum usay phenk dete hain (include_top=False) aur apna head ugate hain jitne classes hamari task ko chahiye.

Diagram

Notice the rhythm: convolution blocks (in red) with more and more channels, each cut by a max-pooling layer (blue) that halves height and width, ending in the fully-connected head — exactly the conv/pool mechanics from Topic 02, just deeper and more regular.

Rhythm par ghor karein: convolution blocks (red mein) jin ke channels barhte jate hain, har ek max-pooling layer (blue) se kata hua jo height aur width aadhi kar deti hai, aur aakhir mein fully-connected head — bilkul Topic 02 ke conv/pool mechanics, bas zyada deep aur zyada regular.

Practice code — run in Google Colab, top to bottom

Blocks must run in order. Copy each block into a Colab cell (Runtime → Change runtime type → T4 GPU makes blocks 6–7 much faster) and run them one by one. We use a 5000-image subset so the whole notebook finishes in minutes on free Colab.
Blocks order mein chalne zaroori hain. Har block ko Colab cell mein copy karein (Runtime → Change runtime type → T4 GPU se blocks 6–7 bohat fast ho jate hain) aur ek ek kar ke run karein. Hum 5000-image subset use karte hain taake pura notebook free Colab par minutes mein khatam ho.
BLOCK 1: Imports

Everything we need: Keras for building models, the pre-built VGG16, and sklearn metrics for evaluation.

Jo kuch chahiye woh sab: models banane ke liye Keras, pre-built VGG16, aur evaluation ke liye sklearn metrics.

# TensorFlow's Keras API: model building, layers, and the VGG16 model itself
from tensorflow.keras.applications import VGG16
from tensorflow.keras.applications.vgg16 import preprocess_input
from tensorflow.keras import layers, models
# Pre-trained VGG16 weights are downloaded from a public Keras mirror (no login needed)
import tensorflow as tf
import numpy as np
import matplotlib.pyplot as plt
from sklearn.metrics import confusion_matrix, ConfusionMatrixDisplay, classification_report
BLOCK 2: Load a CIFAR-10 subset

CIFAR-10 is built into Keras, so loading it is one call. We keep the first 5000 train / 1000 test images so free Colab finishes quickly — classes stay because the data is pre-shuffled.

CIFAR-10 Keras ke andar built hai, toh load karna ek call ka kaam hai. Hum pehli 5000 train / 1000 test images rakhte hain taake free Colab jaldi khatam ho jaye — classes qayam rehte hain kyunki data pehle se shuffled hai.

# CIFAR-10 ships inside Keras, so one call downloads the ready-made train/test split
# (same dataset as Topic 02: 60000 32x32 colour images, 10 classes)
from tensorflow.keras.datasets import cifar10
(X_train_full, y_train_full), (X_test_full, y_test_full) = cifar10.load_data()

# Free Colab is slow, so keep only a subset: first 5000 train / 1000 test images
# Classes are already shuffled, so a slice keeps all 10 labels balanced enough
X_train_raw, y_train = X_train_full[:5000], y_train_full[:5000]
X_test_raw,  y_test  = X_test_full[:1000],  y_test_full[:1000]

# Labels come as a column vector -> flatten to a 1-D array of class ids 0..9
y_train, y_test = y_train.ravel(), y_test.ravel()

# The 10 class names, in label order (airplane=0 ... truck=9)
class_names = ["airplane","automobile","bird","cat","deer",
               "dog","frog","horse","ship","truck"]
print("Train subset:", X_train_raw.shape, "Test subset:", X_test_raw.shape)
BLOCK 3: Resize + ImageNet preprocessing

VGG16 needs its input preprocessed exactly the way ImageNet images were when the weights were learned — otherwise the transferred features see numbers they don't recognise. We also upscale 32×32 → 48×48 so the deep pooling stack doesn't shrink the image to nothing.

VGG16 ko apna input bilkul waise preprocess karna zaroori hai jaise ImageNet images thin jab weights seekhi gayi thin — warna transferred features aise numbers dekhenge jo woh pehchante nahi. Hum 32×32 → 48×48 upscale bhi karte hain taake deep pooling stack image ko mita na de.

# VGG16 refuses inputs smaller than 32x32; we upscale 32->48 so early pooling
# still leaves enough pixels for the deep stack of convolutions
X_train = tf.image.resize(X_train_raw, (48, 48)).numpy()
X_test  = tf.image.resize(X_test_raw,  (48, 48)).numpy()

# VGG16-specific preprocessing: RGB->BGR then zero-centre each channel
# using the ImageNet means the pre-trained weights were trained with
X_train = preprocess_input(X_train)
X_test  = preprocess_input(X_test)
print("After resize + preprocess:", X_train.shape, X_test.shape)
BLOCK 4: Load VGG16 with ImageNet weights and freeze it

This is the transfer-learning moment: weights="imagenet" loads the features Oxford learned from 1.4M images, include_top=False throws away their 1000-class head, and freezing protects those features from our small dataset's noisy gradients.

Yeh transfer-learning ka moment hai: weights="imagenet" Oxford ke 1.4M images se seekhe hue features load karta hai, include_top=False unka 1000-class head phenk deta hai, aur freezing un features ko hamare chhotay dataset ke noisy gradients se bachati hai.

# Load VGG16 WITHOUT its 1000-class ImageNet head but WITH learned ImageNet weights
# weights="imagenet" is the transfer-learning switch: it loads the filters the
# Oxford group learned from 1.4M images instead of starting from random numbers
base = VGG16(weights="imagenet", include_top=False, input_shape=(48, 48, 3))

# Freeze the base: set every weight to non-trainable
# Why: with only 5000 images we would overwrite (destroy) the general ImageNet
# features if our small dataset pushed big gradient updates into the base
base.trainable = False
base.summary()
BLOCK 5: Add our own classifier head

The frozen base ends with 3×3×512 feature maps; we pool them to a 512-number vector and learn a small dense classifier on top — the only part that trains.

Frozen base 3×3×512 feature maps par khatam hoti hai; hum unay ek 512-number vector mein pool karte hain aur upar ek chhota dense classifier seekhte hain — sirf wohi hissa train hota hai.

# Build a small "head": our own classifier that sits on top of the frozen base
model = models.Sequential([
    base,                                        # frozen VGG16 feature extractor
    layers.GlobalAveragePooling2D(),             # average each 1x1x512 feature map -> 512 numbers (48x48 input shrinks to 1x1 through VGG16’s five 2x2 max-pools)
    layers.Dense(128, activation="relu"),        # small fully-connected layer to recombine features
    layers.Dropout(0.3),                         # randomly zero 30% of activations to fight overfitting
    layers.Dense(10, activation="softmax")       # 10 outputs = CIFAR-10 class probabilities
])
model.summary()
BLOCK 6: Compile and train (head only)

Only ~170k head parameters train — the 14.7M base weights sit still. Three epochs on 5000 images is enough to see transfer learning work.

Sirf ~170k head parameters train hote hain — 14.7M base weights apni jagah jamay rahte hain. 5000 images par teen epochs transfer learning ka asar dekhne ke liye kaafi hain.

# Compile: adam optimizer, sparse categorical cross-entropy (labels are ints, not one-hot)
model.compile(optimizer="adam",
              loss="sparse_categorical_crossentropy",
              metrics=["accuracy"])

# Train only the ~170k head weights (the 14.7M base weights stay frozen)
# 3 epochs x 125 steps keeps the run under ~10 minutes on a free Colab GPU
history = model.fit(X_train, y_train,
                    epochs=3,
                    batch_size=40,
                    validation_split=0.15,
                    verbose=1)
BLOCK 7: Evaluate + confusion matrix

Accuracy on the held-out 1000 images, then the confusion matrix (Topic 01) to see which classes the transferred features still confuse — usually cats vs dogs.

Held-out 1000 images par accuracy, phir confusion matrix (Topic 01) taake dekhein ke transferred features kaun si classes ko ab bhi confuse karte hain — aam tor par cats vs dogs.

# Evaluate on the held-out 1000 test images
test_loss, test_acc = model.evaluate(X_test, y_test, verbose=0)
print(f"Test accuracy: {test_acc:.3f}")

# Confusion matrix (Topic 01): which classes get confused with which
y_pred = model.predict(X_test, verbose=0).argmax(axis=1)   # argmax picks the top class
cm = confusion_matrix(y_test, y_pred)
disp = ConfusionMatrixDisplay(cm, display_labels=class_names)
fig, ax = plt.subplots(figsize=(9, 9))
disp.plot(ax=ax, xticks_rotation=45, cmap="Blues", colorbar=False)
plt.title("VGG16 transfer learning - CIFAR-10 (subset)")
plt.tight_layout()
plt.show()

# Per-class precision / recall / F1 to spot weak classes
print(classification_report(y_test, y_pred, target_names=class_names))
BLOCK 8: Predict one image

Use the finished model like a product: show one test image and print the model's ranked class probabilities.

Finished model ko product ki tarah use karein: ek test image dikhayein aur model ki ranked class probabilities print karein.

# Pick one test image and predict it, showing the model's confidence
i = 12
prob = model.predict(X_test[i:i+1], verbose=0)[0]     # softmax over 10 classes
rank = prob.argsort()[::-1]                           # class ids sorted best to worst

plt.imshow(X_test_raw[i])
plt.title(f"True: {class_names[y_test[i]]}")
plt.axis("off")
plt.show()

for c in rank[:3]:
    print(f"{class_names[c]:12s} {prob[c]*100:5.1f}%")
BLOCK 9: Export VGG16 embeddings for other algorithms

The frozen base is also a feature extractor: any image becomes a 512-dim vector. These embeddings are the raw material for the combos below — SVM classification, K-Means grouping, PCA compression.

Frozen base ek feature extractor bhi hai: koi bhi image 512-dim vector ban jati hai. Yeh embeddings neeche wale combos ka raw material hain — SVM classification, K-Means grouping, PCA compression.

# Feature extraction mode: throw away the head, keep the 512-dim VGG16 embedding
# These vectors are reusable input for OTHER algorithms (SVM, K-Means, PCA)
features = base.predict(X_test[:500], verbose=0)
print("Embedding shape:", features.shape)   # (500, 1, 1, 512) before pooling
flat = features.reshape(features.shape[0], -1)
print("Flattened for SVM / K-Means:", flat.shape)   # (500, 512)

Interview Q&A

What is transfer learning and why does it work?
Transfer learning kya hai aur kaam kyun karta hai?
Transfer learning reuses a model trained on one task (source) as the starting point for another (target). It works because early convolutional layers learn generic visual features — edges, corners, textures — that are useful for nearly any image dataset, so only the task-specific top layers need retraining. It turns a weeks-long, million-image training job into minutes on a small dataset.
Transfer learning ek task (source) par trained model ko doosri task (target) ke starting point ke tor par dobara use karta hai. Yeh kaam karta hai kyunki early convolutional layers generic visual features seekhti hain — edges, corners, textures — jo taqreeban har image dataset ke liye useful hain, is liye sirf task-specific top layers ko dobara training chahiye. Yeh hafton ka million-image training job chhotay dataset par minutes mein tabdeel kar deta hai.
Why does VGG16 use only 3×3 filters?
VGG16 sirf 3×3 filters kyun use karti hai?
Stacking three 3×3 convolutions covers the same receptive field as one 7×7 filter but with fewer parameters (2·3²C² < 7²C² per layer comparison) and — crucially — two extra ReLU non-linearities in between, letting the network learn more complex functions. It also made the architecture uniform and simple to reason about, which was itself the paper's point.
Teen 3×3 convolutions stack karne se wohi receptive field milta hai jo ek 7×7 filter se milta hai, lekin kam parameters ke saath (2·3²C² < 7²C² per layer comparison) aur — sab se ahem baat — beech mein do extra ReLU non-linearities, jo network ko zyada complex functions seekhne deti hain. Isay architecture uniform aur samajhne mein aasan bhi bana diya, jo khud paper ka main point tha.
What do weights="imagenet" and include_top=False each do?
weights="imagenet" aur include_top=False har ek kya karti hain?
weights="imagenet" loads the parameters trained on ImageNet instead of random initialisation — the transfer-learning switch. include_top=False drops the final dense layers that output 1000 ImageNet classes, so we can attach our own head with however many outputs our task needs (10 for CIFAR-10).
weights="imagenet" random initialisation ke bajaye ImageNet par trained parameters load karti hai — transfer learning ka switch. include_top=False aakhri dense layers hata deti hai jo 1000 ImageNet classes output karti hain, taake hum apna head laga sakein jitne outputs hamari task ko chahiye (CIFAR-10 ke liye 10).
Why do we set base.trainable = False instead of training everything?
Hum base.trainable = False kyun set karte hain, sab kuch train karne ke bajaye?
With a small dataset, gradients from a few thousand images are noisy and would overwrite the general features the base learned from 1.4M images — catastrophic forgetting on a budget. Freezing the base means only our small head trains: fewer parameters, faster epochs, and much less overfitting. Once the head converges, fine-tuning can cautiously unfreeze the last blocks with a tiny learning rate.
Chhotay dataset ke saath, kuch hazar images ke gradients noisy hote hain aur base ke un general features ko overwrite kar dete jo usne 1.4M images se seekhe thay — budget wala catastrophic forgetting. Base freeze karne ka matlab sirf hamara chhota head train hota hai: kam parameters, fast epochs, aur bohat kam overfitting. Jab head converge ho jaye, toh fine-tuning mein aakhri blocks ko bohat chhotay learning rate ke saath ehtiyat se unfreeze kiya ja sakta hai.
What is the difference between feature extraction and fine-tuning?
Feature extraction aur fine-tuning mein kya farq hai?
Both start from frozen pre-trained weights plus a new head. Feature extraction keeps the base permanently frozen and only trains the head (or skips the head and feeds the embeddings to a classic model like an SVM). Fine-tuning unfreezes some or all base layers after initial training and continues with a very small learning rate so the base specialises to the new data without destroying what it knew.
Dono frozen pre-trained weights aur naye head se shuru hote hain. Feature extraction mein base hamesha ke liye frozen rehti hai aur sirf head train hota hai (ya head skip kar ke embeddings SVM jaise classic model ko de di jati hain). Fine-tuning mein initial training ke baad kuch ya saari base layers unfreeze hoti hain aur bohat chhotay learning rate se training jari rehti hai taake base naye data ke mutabiq specialise ho lekin jo woh already janti thi woh kho na de.
Why did we resize CIFAR-10 images and run preprocess_input on them?
Hum ne CIFAR-10 images resize kyun ki aur un par preprocess_input kyun chalaya?
The pre-trained weights expect inputs in the same numeric regime as ImageNet training: VGG16's preprocess_input converts RGB to BGR and zero-centres channels with ImageNet means. Feeding raw 0–255 RGB pixels would make the transferred filters see out-of-distribution values and the features would degrade. The resize to 48×48 (from 32×32) keeps enough spatial resolution for the five 2×2 pooling layers.
Pre-trained weights input ko ImageNet training jaisi hi numeric regime mein expect karti hain: VGG16 ka preprocess_input RGB ko BGR mein tabdeel karta hai aur channels ko ImageNet means se zero-centre karta hai. Raw 0–255 RGB pixels dene par transferred filters out-of-distribution values dekhte aur features kharab ho jate. 48×48 par resize (32×32 se) paanch 2×2 pooling layers ke liye kaafi spatial resolution bachata hai.
VGG16 is ~138M parameters — why is it considered "simple"?
VGG16 ~138M parameters ki hai — phir bhi "simple" kyun mani jati hai?
Simple refers to architecture, not size. VGG16 is one repeated pattern — 3×3 convolutions, same padding, 2×2 max-pool, doubling channels — with no branches, no exotic layers, no special tricks. That uniformity is why it became the default teaching and transfer-learning backbone, even though later nets (ResNet etc.) beat it with far fewer parameters.
Simple ka matlab architecture se hai, size se nahi. VGG16 ek hi repeated pattern hai — 3×3 convolutions, same padding, 2×2 max-pool, doubling channels — koi branches nahi, koi exotic layers nahi, koi special tricks nahi. Yehi uniformity wajah hai ke yeh default teaching aur transfer-learning backbone ban gayi, halanke baad ki networks (ResNet waghera) ne kam parameters se isay beat kar diya.
How does VGG16 relate to the CNN you built in Topic 02?
VGG16 ka Topic 02 wale CNN se kya taluq hai?
Same machinery, different scale and origin. Your Topic 02 CNN is a small network you trained from scratch: random filters slowly learning edges for CIFAR-10. VGG16 is that same conv/pool/softmax pattern repeated 13 convolutions deep, with filters already trained on ImageNet — comparing the two on the same data quantifies exactly what transfer learning adds.
Machinery same, scale aur origin different. Aap ka Topic 02 CNN ek chhota network hai jo aap ne scratch se train kiya: random filters dheere dheere CIFAR-10 ke liye edges seekhte hain. VGG16 wohi conv/pool/softmax pattern 13 convolutions deep repeat karti hai, filters pehle se ImageNet par trained hain — dono ko same data par compare karna batata hai ke transfer learning exactly kitna add karta hai.

Practical 2 — Binary Classification (Sir Waqas’s code, explained)

The practice above used 10 classes. Real projects often need a YES/NO answer — sick/healthy, cat/dog, fraud/not-fraud. This is binary classification. The code below is your teacher Sir Waqas's, with a harder medical dataset (chest X-rays: NORMAL vs PNEUMONIA). Only 3 things change vs the 10-class version: last layer becomes Dense(1, sigmoid), loss becomes binary_crossentropy, and we can draw a ROC-AUC curve (only possible with 2 classes).

Upar wali practice 10 classes par thi. Asli projects mein aksar YES/NO jawab chahiye hota hai — bimar/sehatmand, cat/dog, fraud/not-fraud. Isay binary classification kehte hain. Neeche ka code aapke teacher Sir Waqas ka hai, lekin ek mushkil medical dataset ke saath (chest X-rays: NORMAL vs PNEUMONIA). 10-class version se sirf 3 cheezein badalti hain: aakhri layer Dense(1, sigmoid) ho jati hai, loss binary_crossentropy ho jata hai, aur ROC-AUC curve bana sakte hain (sirf 2 classes par mumkin).

BLOCK 10: Setup + download the dataset
import kagglehub                      # Kaggle's downloader library (pre-installed in Colab)
import os                              # for joining folder paths
import numpy as np                     # fast array math
import tensorflow as tf                # deep-learning framework
import matplotlib.pyplot as plt        # charts

from tensorflow.keras import layers
from tensorflow.keras.applications import VGG16
from tensorflow.keras.applications.vgg16 import preprocess_input
from sklearn.metrics import confusion_matrix, ConfusionMatrixDisplay
from sklearn.metrics import roc_curve, roc_auc_score    # BINARY-only metrics
from google.colab import files          # to upload YOUR own image later
from tensorflow.keras.utils import load_img, img_to_array

# Download a harder, real-world binary dataset: chest X-rays (NORMAL vs PNEUMONIA)
# 5,856 hospital-grade images from Guangzhou Women and Children's Medical Center
path = kagglehub.dataset_download("tolgadincer/labeled-chest-xray-images")
print("Dataset Path:", path)

# All Kaggle datasets land inside /root/.kaggle/... — kagglehub prints the exact path
data_path = os.path.join(path, "chest_xray")   # the folder that holds train/ and test/
print("Data folder exists:", os.path.exists(data_path))  # sanity check: must print True

kagglehub downloads the dataset straight into Colab — no manual download, no API key. The dataset is complex: medical images where the difference between classes is subtle clouding in the lungs, not obvious shapes like cat vs dog.

kagglehub dataset seedha Colab ke andar download kar deta hai — na manual download, na API key. Yeh dataset complex hai: medical images jahan dono classes ka farq phaiphone mein halka clouding hai, cat vs dog jaise wazeh shapes nahi.

BLOCK 11: Load images from folders (train/test split)
# image_dataset_from_directory reads class names FROM FOLDER NAMES.
# Inside chest_xray/train/ there are 2 subfolders: NORMAL/ and PNEUMONIA/
#   -> the folder name becomes the label. This is "data organized by class".
# validation_split=0.2 + subset="training"  -> 80% of images for training
# same seed=123 + subset="validation"       -> the OTHER 20% for testing
# (same seed = same shuffle = no image appears in both sets = no data leakage)
train_dataset = tf.keras.utils.image_dataset_from_directory(
    data_path + "/train",                # we point at train/ and split it ourselves
    validation_split=0.2,
    subset="training",
    seed=123,
    image_size=(224, 224),               # VGG16's native input size
    batch_size=32                        # 32 images per training step
)

test_dataset = tf.keras.utils.image_dataset_from_directory(
    data_path + "/train",                # held-out 20% from the SAME train folder
    validation_split=0.2,
    subset="validation",
    seed=123,
    image_size=(224, 224),
    batch_size=32
)

class_names = train_dataset.class_names  # ['NORMAL', 'PNEUMONIA'] (alphabetical)
print("Classes:", class_names)

This one function replaces manually loading thousands of images. It reads folders, labels images, shuffles, resizes to 224×224, and packs them into batches of 32. Target variable (teacher's favourite question): the folder name — NORMAL or PNEUMONIA.

Yeh ek function hazaron images manually load karne ka kaam kar deta hai. Yeh folders padhta hai, images ko label karta hai, shuffle karta hai, 224×224 resize karta hai, aur 32 ke batches mein pack karta hai. Target variable (sir ka favourite sawal): folder ka naam — NORMAL ya PNEUMONIA.

BLOCK 12: Frozen VGG16 + binary head (sigmoid)
# Same frozen VGG16 feature extractor as before (transfer learning)
vgg16 = VGG16(weights="imagenet", include_top=False, input_shape=(224, 224, 3))
vgg16.trainable = False          # freeze all 14.7M weights — we only train the head

model = tf.keras.Sequential([
    layers.Input(shape=(224, 224, 3)),
    layers.Lambda(preprocess_input),    # RGB->BGR + zero-centre (inside the model!)
    vgg16,                              # frozen feature extractor -> 7x7x512 maps
    layers.Flatten(),                   # 7*7*512 = 25,088 numbers in one row
    layers.Dense(128, activation="relu"),   # z = w.x + b, relu keeps positives
    layers.Dropout(0.5),                # drop 50% of activations — medical datasets
                                        # are small; strong dropout fights overfitting
    layers.Dense(1, activation="sigmoid")   # <<< BINARY: ONE number between 0 and 1
])
# MATH: sigmoid(z) = 1 / (1 + e^-z)  -> squashes any score into a probability
# Output = P(PNEUMONIA). If it is >= 0.5 -> PNEUMONIA, else NORMAL.

model.compile(optimizer="adam",
              loss="binary_crossentropy",     # <<< BINARY loss (not sparse_categorical)
              metrics=["accuracy"])
# MATH: binary_crossentropy = -[y*ln(p) + (1-y)*ln(1-p)]
#   y=1 (pneumonia): loss = -ln(p)         -> wants p -> 1
#   y=0 (normal):    loss = -ln(1-p)       -> wants p -> 0

Three changes make it binary: Dense(1) instead of Dense(10), sigmoid instead of softmax, binary_crossentropy instead of sparse_categorical_crossentropy. Sigmoid IS the logistic function from Topic 05 — deep learning and logistic regression meet here.

Teen tabdeeliyan isay binary banati hain: Dense(1) Dense(10) ki jagah, sigmoid softmax ki jagah, binary_crossentropy sparse_categorical ki jagah. Sigmoid wahi logistic function hai Topic 05 se — deep learning aur logistic regression yahan milte hain.

BLOCK 13: Train + evaluate
# 5 epochs over ~4,700 training images. On a free T4 GPU: ~4-6 minutes
history = model.fit(train_dataset,
                    validation_data=test_dataset,
                    epochs=5)

loss, accuracy = model.evaluate(test_dataset)   # accuracy on unseen 20%
print("Test Accuracy:", accuracy)

Watch validation accuracy each epoch. If train accuracy climbs but validation stalls — that is overfitting live in front of you (teacher's favourite question, Topic: Core Concepts).

Har epoch validation accuracy dekho. Agar train accuracy chadhti hai magar validation atki rahe — yeh overfitting hai, live (sir ka favourite sawal, Core Concepts page).

BLOCK 14: Predictions + confusion matrix
# Collect TRUE labels and predicted PROBABILITIES over the test set
y_true, y_scores = [], []
for images, labels in test_dataset:          # dataset yields batches of 32
    predictions = model.predict(images, verbose=0).flatten()   # (32,) probabilities
    y_true.extend(labels.numpy())            # real answers 0 or 1
    y_scores.extend(predictions)             # model's P(PNEUMONIA)

y_true = np.array(y_true)
y_scores = np.array(y_scores)
y_pred = (y_scores >= 0.5).astype(int)       # probability -> decision at threshold 0.5
# MATH: threshold t turns probabilities into classes. 0.5 is the default,
# but a hospital can move it: lower t = catch more sick (recall up), higher t
# = fewer false alarms (precision up). This trade-off IS the ROC curve.

cm = confusion_matrix(y_true, y_pred)        # rows=true, cols=predicted (Topic 01)
disp = ConfusionMatrixDisplay(confusion_matrix=cm, display_labels=class_names)
disp.plot()
plt.title("Confusion Matrix — NORMAL vs PNEUMONIA")
plt.show()
# In a hospital: FN (sick patient sent home) is WORSE than FP (healthy re-tested)

The 0.5 threshold is a decision, not math truth. In medical AI, teams often lower the threshold to catch more true cases — the confusion matrix changes even though the model is identical. Great interview point.

0.5 threshold ek decision hai, math ki sachai nahi. Medical AI mein aksar threshold neeche karte hain taake zyada bimar pakre jayein — confusion matrix badal jati hai halanke model same hai. Interview ka zabardast point.

BLOCK 15: ROC-AUC curve (binary-only metric)
# ROC = Receiver Operating Characteristic (from WW-II radar operators!)
# AUC = Area Under the Curve — probability the model ranks a random sick patient
#        ABOVE a random healthy one. 0.5 = coin flip, 1.0 = perfect.
auc = roc_auc_score(y_true, y_scores)   # uses SCORES, not classes — measures ranking

fpr, tpr, thresholds = roc_curve(y_true, y_scores)
# MATH: sweep the threshold from 1 to 0; at each threshold record
#   TPR = TP/(TP+FN) = recall (caught sick)
#   FPR = FP/(FP+TN) = false alarm rate (healthy flagged sick)
# Plot TPR vs FPR -> the ROC curve. Top-left corner = perfect.

plt.plot(fpr, tpr, label=f"AUC = {auc:.3f}")
plt.plot([0, 1], [0, 1], linestyle="--")    # diagonal = random guessing baseline
plt.xlabel("False Positive Rate")
plt.ylabel("True Positive Rate")
plt.title("ROC-AUC Curve")
plt.legend()
plt.show()
print("ROC-AUC:", auc)

Why ROC-AUC beats accuracy: with imbalanced data (e.g. 80% normal), a dumb model predicting ‘always NORMAL’ scores 80% accuracy but AUC 0.5. AUC measures the model's ranking power across ALL thresholds — that is why medical and fraud models report it.

ROC-AUC accuracy se behtar kyun: imbalanced data par (misal 80% normal), ek dumb model jo hamesha ‘NORMAL’ bole 80% accuracy lekin AUC 0.5 pawe gi. AUC model ki ranking power napta hai tamam thresholds par — isi liye medical aur fraud models yehi report karte hain.

Interview questions — binary classification

Why Dense(1, sigmoid) for binary but Dense(10, softmax) for multi-class?
Binary ke liye Dense(1, sigmoid) magar multi-class ke liye Dense(10, softmax) kyun?
One sigmoid output can represent two classes: P(class1)=p, P(class2)=1−p, so probabilities still sum to 1. With 10 classes you need 10 outputs normalized by softmax. Using 2 sigmoid outputs for binary would be wrong — the two numbers would be independent, not competing.
Ek sigmoid output do classes represent kar sakti hai: P(class1)=p, P(class2)=1−p, is liye probabilities ka jawab ab bhi 1 hai. 10 classes ke liye 10 outputs chahiye jo softmax normalize kare. Binary ke liye 2 sigmoid outputs ghalat hote — dono numbers independent hote, muqabla nahi karte.
What is the ROC-AUC curve and when is it better than accuracy?
ROC-AUC curve kya hai aur kab accuracy se behtar hai?
ROC plots True Positive Rate vs False Positive Rate as the decision threshold sweeps from strict to loose; AUC is the area under it = probability that a random positive example scores above a random negative one. It is threshold-independent, so it exposes models that look good only at one lucky threshold, and it stays honest on imbalanced data where accuracy lies.
ROC True Positive Rate aur False Positive Rate ko plot karta hai jab threshold ko sakht se dheela kiya jata hai; AUC iske neeche ka area hai = probability ke koi random positive example random negative se upar score kare. Yeh threshold-independent hai, is liye un models ko expose karta hai jo sirf ek kismat ke threshold par achhe lagte hain, aur imbalanced data par jahan accuracy jhoot bolti hai wahan imandaar rehta hai.
The dataset is 74% PNEUMONIA. Why is 74% accuracy a red flag here?
Dataset 74% PNEUMONIA hai. Yahan 74% accuracy red flag kyun hai?
Because a model that ALWAYS predicts PNEUMONIA — learning nothing — also scores 74%. Accuracy must always be compared to the majority-class baseline. That is why you also check the confusion matrix (is it just predicting one class?) and AUC (does it actually rank patients?).
Kyunki ek model jo HAMESHA PNEUMONIA predict kare — kuch bhi seekhe bina — bhi 74% pawe ga. Accuracy ko hamesha majority-class baseline se compare karna chahiye. Isi liye confusion matrix bhi dekho (kya woh sirf ek class predict kar raha hai?) aur AUC (kya woh waqai rank karta hai?).
